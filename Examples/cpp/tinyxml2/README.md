# TinyXML-2 original methods

`IsUTF8Continuation.lean` is generated from the unchanged
`tinyxml2::XMLUtil::IsUTF8Continuation(const char)` in TinyXML-2 10.0.0,
revision `321ea883b7190d4e85cae5512a12e5eaa8f8731f`, `tinyxml2.h` lines 606–608.
It is an altered typed representation of that source, under the original
[zlib notice](LICENSE-tinyxml2.txt). The original C++ is external/read-only;
there is no handwritten replacement body in this example.

The generic [exporter](../../../extractors/cpp/export_callable.lean) validates
the complete original translation-unit probe before selecting one exact body
occurrence. It emits a `CallableFunction` source literal, so the evaluator
reduces in Lean's kernel without reading the external corpus at proof time.
[provenance.json](provenance.json) pins the source files, complete probe,
frontend, selection path and generated literal. The full probe and local
compiler/library receipts remain external build evidence.

This source-to-IR bridge trusts Clang, the canonical probe, metadata
validation, callable lowering and the representation printer. The kernel
checks the generated literal's execution; it does not authenticate the
capture or prove this translation correct. The complete dependency/capture
provenance and whole-program semantics remain separate obligations.

`proof.lean` proves a successful boolean result for **every** signed 8-bit char:
the helper returns true exactly when the char is negative on the pinned LP64
ABI. This states the original high-bit test, without claiming Unicode
validation. The finite kernel `decide` check uses only `propext`; the
pointwise theorem also lists the standard Lean axioms `Classical.choice` and
`Quot.sound`. No native decision or new axiom declaration is used.

```sh
LEAN_NUM_THREADS=1 prlimit --as=17179869184 -- \
  lake build Examples.cpp.tinyxml2.proof
```

The opt-in differential calls the **original header declaration**, with no
body copy, for all 256 char values at `-O0` and `-O2` under UBSan. It compares
both interpreters and checks cleanup of the object-backed parameter frame.
The test verifies the pinned source and literal hashes before running.

```sh
export LEANCPP_TINYXML2_DIR=/absolute/path/to/pinned/tinyxml2
export LEANCPP_CLANG=/path/to/matching/clang++
LEAN_NUM_THREADS=1 prlimit --as=17179869184 -- \
  python3 extractors/cpp/test_tinyxml2.py
```

## Regenerating the literal

Build the matching plugin as in the [extractor instructions](../../../extractors/cpp/README.md).
From the repository root, choose an absolute probe output path and preserve the
capture's working directory:

```sh
export CPP_PROBE=/absolute/path/to/probe.json
export CPP_AST_PATH=122,14,10
(cd "$LEANCPP_TINYXML2_DIR" && "$LEANCPP_CLANG" --no-default-config \
  -std=c++23 -pedantic-errors -fsyntax-only tinyxml2.cpp \
  -Xclang -load -Xclang "$LEANCPP_PROBE_LIBRARY" \
  -Xclang -plugin -Xclang leancpp-canonical-probe) > "$CPP_PROBE"
LEAN_NUM_THREADS=1 prlimit --as=17179869184 -- \
  lake env lean -j 1 --run extractors/cpp/export_callable.lean \
  "$CPP_PROBE" "$CPP_AST_PATH" Examples.cpp.tinyxml2.IsUTF8Continuation \
  > Examples/cpp/tinyxml2/IsUTF8Continuation.lean
```

The shown path belongs to this recorded capture. For a new environment, inspect
its complete census and use the actual retained helper occurrence; do not assume
that unrelated declarations retain the same array indices. The source hashes
must still match the pinned revision. After successful export, regenerate the
capture-dependent manifest fields and rerun the proof and differential:

```sh
python3 - <<'PY'
import hashlib, json, os
from pathlib import Path
example = Path("Examples/cpp/tinyxml2")
manifest = example / "provenance.json"
record = json.loads(manifest.read_text())
corpus = Path(os.environ["LEANCPP_TINYXML2_DIR"])
for name, expected in record["source_sha256"].items():
    assert hashlib.sha256((corpus / name).read_bytes()).hexdigest() == expected
probe = Path(os.environ["CPP_PROBE"]).read_bytes()
record["probe_sha256"] = hashlib.sha256(probe).hexdigest()
record["probe_bytes"] = len(probe)
record["probe_ast_path"] = list(map(int, os.environ["CPP_AST_PATH"].split(",")))
record["literal_sha256"] = hashlib.sha256(
    (example / "IsUTF8Continuation.lean").read_bytes()).hexdigest()
manifest.write_text(json.dumps(record, indent=2) + "\n")
PY
```

Fresh frontend handles can change the generated bytes. The literal must always
be emitted by the exporter from that complete capture, and its theorem must be
rechecked. This one helper establishes neither instance/class execution nor a
completed language rung or three-corpus execution result.

## Member getters on existing receivers

`NodeGetLineNum.lean` and `AttributeGetLineNum.lean` are generated from the
unchanged `XMLNode::GetLineNum` and `XMLAttribute::GetLineNum` bodies in the same
revision (`tinyxml2.h` lines 755 and 1154). The
[member-getter manifest](member-getters-provenance.json) pins their source,
complete probe, admission/export tools, selection paths and literal hashes.
The original zlib notice and the source-to-IR trust boundary above apply.

`member_getters_proof.lean` proves that each method returns its selected member
and the identical caller memory whenever the supplied receiver/member binding
and read succeed. Kernel-reduced live examples establish non-vacuity. The
[getter contract](../../../docs/cpp-member-getters.md) describes the explicit
existing-object projection: it supplies ownership rather than inferring layout
or running constructors. These methods do not use the aggregate schema API.

```sh
LEAN_NUM_THREADS=1 prlimit --as=17179869184 -- \
  lake build Examples.cpp.tinyxml2.member_getters_proof
LEAN_NUM_THREADS=1 prlimit --as=17179869184 -- \
  python3 extractors/cpp/test_member_getters.py
```

The differential needs the compiler/plugin variables above. It compiles the
unchanged original implementation at `-O0` and `-O2` under UBSan, setting and
reading each private member independently of the getter through the standard
explicit-instantiation access waiver (N4950 [temp.explicit]). Parsing and
construction are native setup, outside the modeled execution. No source patch,
access macro or ABI offset supplies the expected value.

To regenerate, run `export_member_getter.lean` in the same way as the static
exporter, using the actual retained paths (recorded here as `122,15,24` and
`122,20,7`) and namespaces `Examples.cpp.tinyxml2.NodeGetLineNum` and
`Examples.cpp.tinyxml2.AttributeGetLineNum`. Publish output only after a
successful export; regenerate all manifest hashes and rerun the proof and
differential against the matching sources.

## Complete roots and abstract base receivers

`ElementHierarchy.lean`, `DocumentHierarchy.lean` and `BaseGetLineNum.lean` are
generated together from one complete capture. The
[class-subobject manifest](class-subobjects-provenance.json) pins the source,
capture/plugin, tools, selections and literals. Both concrete classes have the
abstract `XMLNode` as a nonvirtual base. The receiver path `[0]` selects that
base, with an identity distinct from its complete root.

`class_subobjects_proof.lean` proves successful original getter execution from
validated complete/base/member observations, preserving caller memory. Concrete
kernel examples run both hierarchies and verify the selected base is abstract.
It also checks the explicit nonvirtual base-view operation on both complete
roots, returning the existing `XMLNode` object identity without changing memory.
The generated hierarchy retains each base edge's effective and written access
labels. The base-view policy accepts the two TinyXML-2 paths because their edge
is public; protected/private paths are refused as `inaccessibleBase`. Access
context lookup, friends and source-level cast execution remain outside this
proof.
The native controls independently set/read the original private member in real
element and document objects, using the standard access waiver described above.
Native construction, parsing and destruction remain oracle setup.

```sh
LEAN_NUM_THREADS=1 prlimit --as=17179869184 -- \
  lake build Examples.cpp.tinyxml2.class_subobjects_proof
LEAN_NUM_THREADS=1 prlimit --as=17179869184 -- \
  python3 extractors/cpp/test_class_subobjects.py
```

Regenerate the two hierarchies with `export_class_hierarchy.lean` at the actual
complete class paths (recorded as `122,21` and `122,23`), and the base getter with
`export_member_getter.lean` at `122,15,24`. All three must come from the same
capture: frontend handles cannot be combined across independent captures.
Regenerate the manifest hashes, rebuild the proof and rerun the native controls.
