# Standardized AST envelope — schema ada-0.1 (Ada payload)

One JSON document per **compilation** — which in Ada is not one per file
(§0.3). The envelope is language-neutral and mirrors
`docs/envelope-schema.md` (Python), `docs/c-envelope-schema.md` (C) and
`docs/sv-envelope-schema.md` (SystemVerilog); the node vocabulary inside
mirrors the language's own frontend — here libadalang, node kind names
preserved exactly. Extractors must emit **deterministic** output: same input
bytes ⇒ same output bytes.

**Status: the Ada charter's inch 4 ([docs/ada-charter.md](ada-charter.md)
§5.4). The schema is fixed; `extractors/ada/extract.py` is inch 5 and does
not exist yet.**

**THE NODE TABLE IS A CHECK, NOT A CLAIM.** §3 does not list a vocabulary,
because inch 2's frontend census has not produced one and **a table chosen
here would be a claim about Ada written by someone who had not run a
parser.** What §3 fixes instead is the RULE the table must satisfy and the
gate that enforces it. This follows the ES lane's inch 3 (`docs/backlog.md`
§L66-67) and the C lane's §4.4, where every vocabulary row was DERIVED from a
landed census rather than chosen.

## 0 What is different about the Ada envelope, and every difference was measured

Five, each forced by a measurement or a ruling rather than by taste.

### 0.1 `language_version` is first-class, and Ada is why the field exists

[docs/family-architecture.md](family-architecture.md) §1.5 made
`language_version` a first-class top-level field carrying the registry's
edition token. Ada is the tier where it earns its keep on day one:
[docs/ada-charter.md](ada-charter.md) §1.3 measured that **the ARM is Ada
2022 and the official suite is ACATS 4.2, which is Ada 2012** — two editions
apart, forced rather than chosen. So **both tokens are live from the first
envelope**, and an envelope that could not say which one it is would be
ambiguous about the program it describes. Annex J is a whole annex of
obsolescent features; "the same source under a different edition" is a real
program difference here, not a hypothetical.

The ingester REFUSES a `language_version` mismatch, exactly as
`load_c_program` already refuses a `profile_id` mismatch.

### 0.2 THE TOP-UNIT EDGE — a file name is NOT a unit name, and Ada is worse than SystemVerilog

`docs/backlog.md` §L67 records the SV lane publishing a wrong diagnosis
because a `--top` derived from the FILENAME could not resolve
`cv32e40p_register_file_ff.sv`, whose module is `cv32e40p_register_file`.
Read from the envelope's own `top`, it regenerated byte-identically.

**Ada has the same hazard by CONVENTION rather than by accident**, and the
ACATS User's Guide says so itself: file names *"conform to MS-DOS naming
conventions; therefore they may be shorter than the software name"*, and
*"in some cases, the structure of the test requires that the file name be
different from the Ada unit."* Worse, the eighth character of a multi-file
test's name is a **compilation-order digit**, so for every multi-file test
the file name is systematically not a unit name.

Measured with GNAT itself as the oracle (`gnatchop -w` names each output
after the unit it contains, so the chopped names ARE the unit names):
`B3710010.A` holds units `b371001_0`, `b371001_1` and the child unit
`b371001_1-child_1`; `B3710013.A` holds `b371001_1`. **No `-top` derived
from those file names resolves.**

> **RULE: the compilation units are read from the ENVELOPE, never derived
> from a path.** `compilation_units` is a first-class, ORDERED list (§1), and
> the round-trip gate (§5) checks it.

### 0.3 One envelope is one COMPILATION, not one file — and order is part of the test

C's envelope is one translation unit and the translation unit is one file.
Ada's is not: a compilation may hold several compilation units, a test may
span several files, and **the compilation ORDER is part of the test**,
encoded in the eighth character of the file name. Measured on ACATS 4.2:
**248 of 4,188 tests span more than one file**
(`docs/ada-suite-census.json`).

So `source_files` and `compilation_units` are both lists, both ordered, and
the order is the extractor's output rather than the reader's inference.

### 0.4 THE SOURCE-PATH SPELLING EDGE — the recorded path is part of the envelope

§L67 again, measured there: regenerating SV envelopes with absolute paths
where the envelope recorded repo-relative ones made **all 18 differ, by
exactly the string-length delta.** The path is not metadata; it is content.

Two consequences here, and Ada needs both more than its siblings do because
its corpus is cross-repo and 41 MB, so nothing about it is in-tree:

* **`source_files[].path` is the recorded SPELLING**, and the extractor takes
  a `--source-name` override for exactly the reason `extractors/c/extract.py`
  has one: *the corpus is cross-repo and a path relative to this root would
  be a fiction*.
* **An envelope whose recorded paths are absolute into somebody's scratch
  directory is unreproducible anywhere**, and the round-trip gate must
  report that with the offending path rather than pass it silently — §L67's
  3 SKIPs are the precedent and the wording is deliberate.

### 0.5 CERR-GRADE SPANS AND THE ACATS MARKINGS — the grader ruling reaching back

[docs/ada-charter.md](ada-charter.md) §6.3 ruled that the scoreboard is a
**trace emitter** and the ACAA's own `GRADE` issues our verdicts (§4.4).
That decision lands in this schema, two inches before the scoreboard exists,
because a trace emitter cannot be retrofitted onto an envelope that threw
away what a trace row needs.

* **Every node carries `line`, `col`, `end_line`, `end_col`.** A `CERR`
  record carries a line and a position, and the ACATS User's Guide calls the
  line *"critical to the correct operation of the grading tool"*. A span the
  ingester dropped is a verdict we cannot produce.
* **The ACATS markings are carried out of the COMMENTS.** `-- ERROR:`,
  `-- OK`, `-- POSSIBLE ERROR:`, `-- OPTIONAL ERROR:` and `-- ANX-C RQMT`
  are the expected result of **1,484 B tests and 71 L tests — 37.1% of the
  official suite** — and they live in comments an AST discards. Measured
  totals: 16,404 `ERROR:` marks, 7,568 `OK`, 584 `POSSIBLE ERROR:`, 313
  `OPTIONAL ERROR:`, 167 `ANX-C RQMT`.

  They are recorded in a **separate `markings` array**, not attached to
  nodes, and the reason is a rule the family already has: the payload is what
  the frontend produced, and a marking is what the SUITE said. Attaching them
  to nodes would make the AST depend on the corpus.

## 1 Envelope

```json
{
  "schema_version": "ada-0.1",
  "language": "ada",
  "language_version": "Ada2012",
  "frontend": {"name": "libadalang", "version": "libadalang-26"},
  "profile_id": "ada-profile-0.1",
  "source_files": [
    {"path": "acats42/support/report.a", "sha256": "<hex>", "line_endings": "lf"}
  ],
  "compilation_units": [
    {"name": "Report", "kind": "PackageDecl", "file": 0, "order": 0,
     "span": {"line": 59, "col": 1, "end_line": 190, "end_col": 12},
     "decl": { <node> }}
  ],
  "markings": [
    {"kind": "ERROR", "file": 0, "line": 99, "col": 12,
     "end_line": 99, "end_col": 43, "text": "type mismatch"}
  ],
  "unsupported_count": 0,
  "lean_blocks": []
}
```

**Field notes, each carrying its reason:**

* `language_version` — the registry's edition token (§0.1). Mismatch is a
  loud refusal.
* `frontend.version` is the **FAMILY**, never the point release. That
  correction is recorded twice in `docs/backlog.md` and cost 53 files of
  re-extraction the second time; reproducing it in a new lane, having read
  the entry, would be inexcusable.
* `source_files[].line_endings` is `"lf"` or `"crlf"` and it is **not
  decoration**. Measured: the ACATS ZIP delivery ships CRLF, and the ACAA's
  own `SUMMARY` tool dies with an unhandled Ada exception on every CRLF
  source — **0 of 120 files summarized as shipped, 150 of 150 after `\r`
  removal** (`docs/backlog.md` §L69). An envelope that did not record which
  it saw could not explain a byte-count discrepancy against the same
  nominal source.
* `compilation_units[].file` indexes `source_files`; `order` is the
  compilation order, from the file name's eighth character where it has one
  and from file order otherwise. **Both are recorded, never derived at read
  time** (§0.2).
* `markings[].file` likewise indexes `source_files`. `text` is the
  description the test author wrote on the marking line, kept because a
  human reading a failure needs it; it is **never** matched against — the
  User's Guide is explicit that only the LOCATION of an error is graded.
* `unsupported_count` is a top-level integer so a scoreboard can reject a
  vacuous ingest without walking the tree (§5, and
  [docs/family-architecture.md](family-architecture.md) §5.3: a run that
  executed nothing must never score as agreement).
* `lean_blocks` is `[]` for Ada and exists so the envelope stays
  language-neutral.

**Cache key**:
`<stem>-<sha256(sources)[:16]>-<sha256(extract.py)[:8]>-<profile_id>-<language_version>`
— the existing `extractor_digest()` discipline plus the profile plus the
edition, because an Ada envelope is a function of (sources, extractor,
profile, EDITION).

## 2 Spans

Every node carries

```json
"span": {"line": 160, "col": 1, "end_line": 164, "end_col": 12}
```

All four are required (§0.5). Ada has no preprocessor in the C sense, so
there is no spelling/expansion split to carry — but it does have the ACATS
`.TST` macro files (62 of them, measured), and those are **expanded before
extraction**, with the expansion recorded in `source_files[].path`. An
envelope never describes an unexpanded `.TST`.

## 3 The node vocabulary — a CHECK, not a claim

**This section deliberately contains no table.**

`docs/ada-charter.md` §3.1 measured, from libadalang's grammar file, that Ada
has **316 concrete node kinds against C's 45** — a 7× multiplier. Choosing a
subset of 316 kinds here, before any parser has run on any Ada, would be
exactly the kind of unverified claim the C lane's §1.1 built its instrument
to prevent.

What is fixed now is the rule and the gate:

1. Inch 2's `harness/ada_construct_census.py` emits
   `docs/ada-construct-census.json`, whose `node_kinds` is the vocabulary the
   BUILT frontend reports on the corpus.
2. `docs/ada-envelope-schema.md` gains its table by GENERATION from that
   file, never by hand.
3. A check asserts the schema's table and the census's `node_kinds` are the
   same set — **neither a subset nor a superset**. "What the ingester
   accepts" and "what the corpus contains" cannot silently drift apart.
4. Anything outside the table becomes an `Unsupported` leaf (§4) carrying the
   libadalang node class and ≤200 characters of source text, and increments
   `unsupported_count`.

Until step 1 lands, the honest statement is: **the vocabulary is unknown and
this document says so.**

## 4 `Unsupported`

```json
{"kind": "Unsupported", "node_class": "TaskTypeDecl",
 "text": "task type Worker is ...",
 "span": {"line": 88, "col": 4, "end_line": 92, "end_col": 16}}
```

Contract, unchanged from the other lanes: the extractor **never fails on
valid Ada**. Anything outside the pinned vocabulary becomes a leaf naming the
frontend's own node class and ≤200 characters of source. Hard errors — an
unreadable file, a frontend diagnostic on a source the suite says is legal, a
profile or edition mismatch — exit non-zero and say why.

`node_class` is libadalang's name preserved exactly, for the same reason the
C envelope preserves clang's: a refusal that cannot be traced back to a
frontend concept is one a human cannot act on.

## 5 Determinism, and the round-trip gate

* `json.dump(..., indent=2)` with the key order specified above.
* A double run on the same input is byte-identical.
* **No absolute paths in the payload.** `source_files[].path` is the
  recorded spelling (§0.4); `span` carries line/column only.
* `markings` sorted by `(file, line, col)`; `source_files` in extraction
  order; `compilation_units` in COMPILATION order.

**`harness/ada_round_trip.py` (inch 5) encodes the rule with all four of its
edges**, three of them §L67's and the fourth Ada's own:

| edge | what it checks | why |
| --- | --- | --- |
| **schema version** | the envelope's `schema_version` is the one this extractor emits | §L67 |
| **top units** | regeneration uses `compilation_units`, never a path-derived name | §0.2 — measured to be unresolvable in Ada |
| **source-path spelling** | regeneration records the same spelling the envelope did | §L67 — made all 18 SV envelopes differ |
| **edition** | regeneration uses the envelope's `language_version` | §0.1 — Ada's forced version pair |

And it obeys §L67's two behavioural rules: it **never writes into the repo**,
and an envelope it cannot reproduce is reported **with the missing path**
rather than passing silently.

## 6 What the ingester will check, and why the census is its oracle

`LeanModels/Ada/Json.lean` (inch 6) ingests this envelope into a Lean AST
literal. Its `#guard`s assert structural facts **another instrument
independently knows** — for `Report`'s specification, the M1 round-trip unit
(`docs/ada-charter.md` §5.7):

| assertion | value | known by |
| --- | ---: | --- |
| compilation units in the envelope | 1 | the schema |
| subprogram declarations | 15 | `Report`'s spec, counted |
| of them procedures | 6 | ditto |
| of them functions | 9 | ditto |
| `File_Num`'s range | `1 .. 5` | ditto |
| unsupported nodes | 0 | `unsupported_count` |

Two instruments, two paths, one answer — the ingester is checked against a
measurement rather than against itself. Non-vacuity is checked the way the C
lane checks it: **flip a count and Lean must report the failing expression.**

## 7 Honest limits

* **The vocabulary is a corpus fact, not an Ada fact**, and it is not even
  that yet (§3). 316 kinds is what libadalang's grammar declares; what an
  ACATS corpus actually reaches is inch 2's measurement.
* **`markings` is an ACATS concept, not an Ada one.** A non-ACATS Ada source
  produces an empty array. The field is in the language-neutral envelope
  because the CORPUS is the tier's driver artifact
  (`docs/ada-charter.md` §4.3), not because Ada has marked comments.
* **No semantics are implied anywhere in this document.** The envelope
  describes what the frontend parsed. Whether any of it can be RUN is M2's
  question, and there is no M2.
* **The `line_endings` field records what the extractor saw, not what the
  ACAA distributes.** Both deliveries exist; the ZIP is CRLF and the tar is
  the likely LF-clean route. The tier does not depend on which — it records.
