# Standardized AST envelope — schema sv-0.1 (SystemVerilog payload)

One JSON document per source file, written by
`python3.12 extractors/sv/extract.py <file.sv> [more.sv ...]` (run from the
repo root) as `<file>.sv.json` next to each source. This document is the
normative contract for the Lean ingester (`LeanModels/Sv/**`): every node kind,
field name, and invariant the ingester may rely on is listed here.

The envelope is language-neutral and mirrors `docs/envelope-schema.md` (the
Python payload); the node vocabulary inside `design` is the SV M0 tier of
`docs/sv-design-m0.md`. Widths are **elaborated** widths from pyslang's
compilation (parse + elaboration), not raw syntax — e.g. the unbased unsized
literal `'0` in an 8-bit context is emitted as an 8-bit `Literal`.

Guarantees:

* The extractor **never fails on valid SystemVerilog**. Anything outside the
  vocabulary below becomes `{"kind": "Unsupported", ...}` at the closest
  enclosing node that can no longer be represented; surrounding structure is
  preserved (e.g. a supported assignment whose RHS contains a function call
  keeps its `BlockingAssign` shape with an `Unsupported` value).
* **Deterministic**: same input bytes (and same pyslang version) ⇒ same output
  bytes. `json.dump(..., indent=2)` + one trailing newline, ASCII-escaped
  strings, and fixed key order: `kind` first, then `span`, then the node's
  remaining fields in exactly the order of the tables below. A parsed envelope
  re-serialized with `json.dumps(obj, indent=2) + "\n"` reproduces the file
  byte-for-byte.

## Envelope

```json
{
  "schema_version": "sv-0.1",
  "language": "systemverilog",
  "frontend": {"name": "pyslang", "family": "pyslang-11"},
  "source_file": "Examples/system-verilog/adder/adder.sv",
  "source_sha256": "<hex sha256 of the source bytes>",
  "design": {"kind": "Design", "modules": [<module>...], "others": [<Unsupported>...]},
  "lean_blocks": []
}
```

**`frontend` is stamped by FAMILY, never by point release** (`pyslang-11`,
not `11.0.0`). The family is what the envelope depends on — pyslang 11.x
parses and elaborates the same way, and the patch digit is not a semantic
input. Stamping the point release put a version string in the bytes of
every envelope, which was harmless while the round-trip gate was
simulator-gated and SKIPped, and became a live hazard the moment that gate
became an unconditional CI step against an unpinned `pip install pyslang`:
the next patch release would have reported all 21 envelopes as `DIVERGE`
on every PR, for a reason unrelated to any change. Same spelling as
`extractors/sv/census.py`, so the two instruments agree.

**Three envelopes still carry the old `"version": "11.0.0"` key**, and
deliberately so: `alu_div`, `ff_one` and `popcnt` under
`Examples/system-verilog/` record `source_files` as absolute paths into a
scratch directory on a machine that no longer exists, so they cannot be
regenerated by anyone. `harness/sv_round_trip.py` reports them as
`REFUSE sources-not-in-tree` with **live=false** and never compares their
bytes. They were left untouched rather than hand-edited, because editing
them would make them look regenerated when they cannot be.

Top-level key order: `schema_version`, `language`, `frontend`, `source_file`,
`source_sha256`, `design`, `lean_blocks`. `source_file` is the (normalized,
`/`-separated) path exactly as passed on the command line. `lean_blocks` is
reserved and always `[]` in M0 (companion blocks are not scanned).

`design.modules` holds one `Module` per **top-level** module instance, in
elaboration (source) order. M0 is single-module; module instantiations inside a
module appear as `Unsupported` members, and `$unit`-scope compilation-unit
members (imports, unit variables, ...) appear as `Unsupported` nodes in
`design.others` (normally `[]`).

## Spans

Every node carries `"span"`: `{"line": L, "col": C, "end_line": EL,
"end_col": EC}` — slang's numbers: **1-based** lines and columns, end
**exclusive**. `span` may be `null` when no source range is available (only on
synthesized/degenerate nodes; never on the M0 examples).

## `Unsupported`

```json
{"kind": "Unsupported", "span": {...}, "sv_kind": "<tag>", "text": "<source text, <= 200 chars>"}
```

May appear anywhere a module member, port, decl, process, statement, or
expression is expected. `text` is the exact source slice of the offending
construct (whitespace-stripped, truncated to 200 chars, possibly `""`).
`sv_kind` is the slang AST class name, optionally qualified with `:detail`
(mirroring the Python lane's `"BinOp:Div"` convention). Tags the extractor
emits:

| tag | meaning |
|---|---|
| `<SlangClass>` | node class outside the vocabulary, e.g. `ForLoopStatement`, `CallExpression`, `ElementSelectExpression`, `RangeSelectExpression`, `ReplicationExpression`, `StringLiteral`, `RealLiteral`, `EmptyStatement`, `VariableDeclStatement`, `CaseStatement`, `InvalidStatement`, `InvalidExpression` |
| `InstanceSymbol:Instance`, `SubroutineSymbol:Subroutine`, `ParameterSymbol:Parameter`, ... | module member kinds outside M0 (class name `:` symbol kind) — routed to the module's `others` list |
| `ProceduralBlockSymbol:Initial` / `:Final` / `:AlwaysLatch` | process kinds outside M0 |
| `ProceduralBlockSymbol:NoEventControl` | `always` / `always_ff` whose body is not an event-controlled statement |
| `TimedStatement:<TimingClass>` | timing-control classification — supported integral-literal `#d` forms become `Delay`, and simple nested `@(posedge sig)` / `@(negedge sig)` / `@(sig)` forms become `WaitEvent`; unsupported delay expressions, event lists, and `TimedStatement:ImplicitEventControl` for `@*` remain loud |
| `SignalEventControl:BothEdges` | edge other than `posedge`, `negedge`, or a bare signal expression |
| `SignalEventControl:iff` | `@(posedge clk iff ...)` |
| `SignalEventControl:clock` | edge expression that is not a 1-bit identifier |
| `AssignmentExpression:compound` | compound assignment whose scalar binary operator is outside the admitted set or whose target is not a plain identifier |
| `AssignmentExpression:compound-width` | compound assignment whose elaborated operands do not share the destination width |
| `IntraAssignment:<reason>` | unsupported intra-assignment control, value, destination or context; blocking controls in the admitted surface lower to capture/wait/copyback, while nonblocking publication remains loud |
| `AssignmentExpression:target` | assignment LHS that is not an admitted identifier/select/concatenation target (including dynamic or aggregate forms; a constant out-of-bounds fixed-array write is lowered to `Empty` per §7.4.5) |
| `ExpressionStatement:<Class>` | expression statement that is not an assignment (`i++;`, void call, ...) |
| `StaticLocal:initializer` | static procedural initializer outside the closed pure pre-process value fragment |
| `StaticLocal:initializer-order` | pre-process initializer reads another procedural static store whose order is not represented |
| `ContinuousAssignSymbol:delay` / `:form` | `assign #5 ...` / malformed continuous assign |
| `ConditionalStatement:Unique` / `:Unique0` / `:Priority` / `:multi` / `:pattern` | `unique`/`priority` if, multiple `&&&` conditions, `matches` pattern |
| `ConditionalExpression:multi` / `:pattern` | same, for `?:` |
| `BlockStatement:JoinAll` / `:JoinAny` / `:JoinNone` | `fork ... join*` |
| `BinaryExpression:<Op>` / `UnaryExpression:<Op>` | operator outside the M0 set, slang enum name (e.g. `BinaryExpression:Divide`) |
| `ConversionExpression:width` | **width mismatch in source**: an implicit conversion that changes bit width (M0 has no implicit extension/truncation rules) |
| `ConversionExpression:Explicit` / `:BitstreamCast` / `:StreamingConcat` | explicit casts |
| `NamedValueExpression:<SymbolKind>` | identifier that does not name a variable/net (e.g. `:Parameter`) |
| `PortSymbol:InOut` / `:Ref` | port directions outside in/out |
| `PortSymbol:...`, `VariableSymbol:...`, `NetSymbol:...` with `:2state` / `:range` / `:type` | unsupported declared type: 2-state nets or symbolic declarations, multidimensional packed ranges, dynamic/queue or nonintegral types (real, string, ...); the legacy/self-check path admits one-dimensional packed scalar ranges, bounded fixed-unpacked integral arrays (including flattened multidimensional cells), and untagged packed struct/union vectors |
| `NetSymbol:<NetKind>` / `:delay` | net kinds other than `wire` (`Tri0`, `WAnd`, ...), net delays |
| `NetSymbol:TriReg` | charge-storage net with driver release, capacitive retention, charge strength or decay |
| `NetSymbol:Tri0` | implicit pull-0 net with strength-sensitive four-state driver resolution |
| `NetSymbol:Tri1` | implicit pull-1 net with strength-sensitive four-state driver resolution |
| `NetSymbol:Tri` | resolved-wire net requiring a general four-state driver set and strength resolution |
| `NetSymbol:Interconnect` | hierarchical net requiring connected-port topology and per-bit net-type resolution |
| `ExtractorInternal:<PyException>` | defensive catch-all: the extractor itself failed on this node (should not occur; `span` is `null`, `text` is the Python error) |

The tag list may grow with the tier; ingesters must treat **any** unknown
`sv_kind` as simply "unsupported" (the interpreter returns `.unsupported` when
an `Unsupported` node is reached).

The measured two-state declaration boundary and its representation rationale
are recorded in [`sv-two-state-boundary.md`](sv-two-state-boundary.md).

### Expression event controls

`SignalEventControl:clock` covers event controls whose sampled operand is an
expression rather than a one-bit identifier. IEEE §9.4.2 compares the complete
value-change result across activations and applies the four-state edge rules to
that result; a multibit edge uses its least-significant bit. The envelope has
no sampled-value register, dependency set, result-change filter, or
aggregate-to-singular conversion, so concatenations, reductions, conditionals,
operators and selected expressions remain explicit unsupported nodes. They are
not rewritten to one operand or an arbitrary selected bit. See the
[event-expression boundary](sv-event-expressions.md).

### Level-sensitive waits

`WaitStatement` is a source-level `wait (expression)` whose condition is
sampled on entry and re-evaluated after relevant updates until it is true.
An already-true condition does not block; a false condition retains the
process continuation and its four-state result. The envelope has no
level-wait dependency set, condition sampler or re-entry registration, so
conjunctions, disjunctions, negated conditions, named-event state and
same-time publication interactions remain explicit unsupported nodes. A wait
is not rewritten as an edge wait or an immediate body execution. See the
[wait-statement boundary](sv-wait-statements.md).

## Module

Key order: `kind`, `span`, `name`, `ports`, `decls`, `processes`, `others`.

```json
{"kind": "Module", "span": {...}, "name": "adder",
 "ports": [<port>...], "decls": [<decl>...], "processes": [<process>...], "others": [...]}
```

Members are routed by category, each list in source order: `ports` (port list
entries), `decls` (module-level variables and nets, **excluding** the internal
symbols that back ANSI ports — a port appears only in `ports`), `processes`
(procedural blocks and continuous assigns), `others` (everything else —
functions, parameters, instances, generate blocks, ... — as `Unsupported`;
`[]` on M0-clean sources). Statement-level `begin/end` scope symbols are
elaboration artifacts and are silently skipped (their statements appear inside
the owning process body).

### Port

Key order: `kind`, `span`, `name`, `dir`, `width`, optional `signed`, optional `two_state`, optional `init`.

```json
{"kind": "Port", "span": {...}, "name": "a", "dir": "in", "width": 8,
 "signed": true}
```

`dir` ∈ `"in" | "out"`. `width` is the elaborated bit width (scalar `logic` ⇒
`1`). Legacy integral variable ports admit scalar, `[W-1:0]` packed and
predefined integer types (`byte`, `shortint`, `int`, `longint`, `integer`,
`time`). A four-state type omits `two_state`; a two-state **input or output
variable** carries `"two_state": true`. Startup and every input stimulus
convert x/z bits to zero before expression evaluation. The time-zero runner
models an unconnected four-state input as z and a two-state input as zero;
the cycle runner models a connected, initially unknown external driver.
Signed types carry optional `signed: true` metadata independently of their
state count. Two-state nets, reversed-range, aggregate, symbolic two-state
and symbolic signed declarations remain `Unsupported`.

`init`, when present, retains the input's default expression or the output
variable's initializer, including two-state conversion. The time-zero runner
evaluates it before processes execute. The connected cycle runner ignores
input defaults and evaluates closed output initializers; state-dependent
initializers are loud there. Invalid output-net port initializers remain
loud, rather than being mistaken for variable startup. A separate internal
initializer on an input variable also remains loud until its initialization
and incoming-driver interaction is modeled.

### Declarations

Key order: `kind`, `span`, `name`, `width`, optional `signed`, `init`.

```json
{"kind": "Var", "span": {...}, "name": "a", "width": 8, "signed": true, "init": <expr> | null}
{"kind": "Net", "span": {...}, "name": "w", "width": 8, "signed": true, "init": <expr> | null}
```

`Var` = `logic`/`reg` variable; `Net` = `wire`. Same type restrictions as
ports (4-state, scalar or `[W-1:0]`; other net kinds, delays,
2-state/reversed-range/multi-dim types ⇒ `Unsupported`; signedness is retained
as metadata). `init` is the
declaration initializer, already width-resolved. LRM note: a **Var** initializer
is a time-0 assignment (the M0 examples use exactly this); a **Net** initializer
is per LRM an implicit *continuous assign* driver — no M0 example uses one, and
the ingester may treat a `Net` with non-null `init` as it treats `Assign`.

An admitted shallow unpacked union uses the same `Var` shape with optional
`unpacked_union_cell: true`. Equal-width integral members all resolve to that
one `name`, preserving their aliasing; unequal-width, mixed-state, tagged, and
nested union declarations remain `Unsupported`.

A blocking whole-copy between two admitted union values is emitted as the
ordinary `BlockingAssign` shape with `unpacked_union_whole_copy_lowered: true`;
its `Ident` target and value name the two shared vector cells. Nonblocking,
timed, mixed-shape, and member-to-whole copies remain unsupported.

## Processes (`processes` list entries)

| kind | key order / fields |
|---|---|
| `AlwaysPosedge` | `kind`, `span`, `style` (`"always_ff"` \| `"always"`), `clock` (string: the 1-bit clock identifier), `body` (stmt) |
| `AlwaysComb` | `kind`, `span`, `body` (stmt) |
| `Assign` | `kind`, `span`, `target` (expr: `Ident`, a select, or semantic-tier `ConcatTarget`), `value` (expr) — continuous `assign` |
| `Initial` | `kind`, `span`, `body` (stmt) — scheduler-facing retained process; the timed loader admits one or more in source order |
| `Always` | `kind`, `span`, `body` (stmt), `always_lowered: true` — legacy plain source repetition through the retained loop interface |

`AlwaysPosedge` covers exactly `always_ff @(posedge clk) ...` and
`always @(posedge clk) ...`; `style` records which keyword the source used —
**M0 cycle semantics treats both identically** (edge-phase processes). Any
other sensitivity stays unsupported in the M0 cycle path. The legacy
scheduler envelope can instead carry `Initial` or plain `Always` processes;
the latter retains its complete source body, including admitted delay, bare
signal and negative-edge controls. Unsupported body nodes remain visible.
Event lists, `@*`, `iff`, level waits and `always_latch` remain loud; see [the
implicit-event boundary](sv-implicit-events.md) for the inferred-read-set
contract. `body`
is a single statement node (often `Block` or `If`).

The scheduler-facing timed loader admits `Initial`, plain `Always`, and
`AlwaysPosedge` processes. Initial bodies run from Active at time zero;
plain `Always` compiles to one ready true-condition loop, with no separate
arm. Each canonical clocked process is lowered to a retained `WaitEvent` followed by
its body and re-armed after completion. The legacy self-check runner remains
initial/time-zero-only and refuses non-initial processes and timed nodes.
Frontend errors in a design containing `always_lowered` are a design-level
barrier. Static scalar storage now hoists before process entry; actual automatic
scalars retain per-entry initialization. Already-admitted automatic fixed-array
cells retain their existing reinitialization rule. See
[procedural lifetimes](sv-procedural-lifetimes.md).
See [plain always procedures](sv-always.md).

## Statements

Simple immediate `assert`/`assume`/`cover` checks in the legacy schema lower
to `If`, with `immediate_assertion: "assert" | "assume" | "cover"` and
`assertion_lowered: true` provenance. The condition and action statements
retain source order. An omitted assert/assume failure action becomes an
`Unsupported` else branch tagged `ImmediateAssertion:implicit-error`;
unsuccessful cover has no else branch. Deferred checks, null failure actions,
unsupported conditions/actions and symbolic-mode checks remain loud.
Frontend errors in a design containing the lowering are a design-level
barrier. See [the contract](sv-immediate-assertions.md).

The implicit-error branch remains an explicit unsupported else node: the
envelope does not carry portable diagnostic text, status, source-location
footer or coverage-observation state. Repricing details are in
`extractors/sv/immediate_assert_error_reprice.py`.

Qualified `unique0 case` statements remain explicit
`CaseStatement:Unique0` unsupported nodes. The ordinary case lowering has no
all-item overlap check or unique0 status, while treating no-match as an error
would contradict the qualifier's semantics. See [the unique0-case boundary](sv-unique0-cases.md)
and `extractors/sv/unique0_case_reprice.py`.

Qualified priority `if` statements remain explicit
`ConditionalStatement:Priority` unsupported nodes. The ordinary conditional
lowering can preserve first-match selection but has no listed-order priority
status, no-match diagnostic channel or retained check state for a waiting
body. See [the priority-if boundary](sv-priority-if.md) and
`extractors/sv/priority_if_reprice.py`.

Qualified priority case statements remain explicit
`CaseStatement:Priority` unsupported nodes. The ordinary case lowering can
preserve first-match selection but has no priority status or no-match
diagnostic channel, and no retained priority-check state for a waiting body.
See [the priority-case boundary](sv-priority-cases.md) and
`extractors/sv/priority_case_reprice.py`.

Qualified `unique if` statements remain explicit
`ConditionalStatement:Unique` unsupported nodes. The ordinary `If` lowering
retains first-match behavior but has no all-condition uniqueness check,
no-match/overlap diagnostic channel, Observed-region report state, or pending
report flush tied to a retained process. See [the unique-if boundary](sv-unique-if.md)
and `extractors/sv/unique_if_reprice.py`.

Deferred `#0` and `final` assertions remain explicit
`ImmediateAssertion:deferred` members. The envelope has no Observed/Postponed
sampling, pending-report maturity, deferred action restriction or
end-of-simulation ordering state; see the deferred repricing instrument
`extractors/sv/immediate_assert_deferred_reprice.py`.

The legacy/self-check extractor also lowers unqualified ordinary integral
`case` statements into nested `If` nodes with `Binary` `===` conditions.
Each lowered `If` carries optional `case_lowered: true` provenance; the
existing statement ingesters need no additional constructor. Subject and
label expressions retain slang's whole-case context conversions and must
belong entirely to the admitted pure integral fragment. Purity is checked
over the bound source tree before constant conversion, so a binder-folded
call or increment cannot disappear into an admitted literal. Source-order
first-match search ends in the source default (if any), independent of
its original placement. Unqualified `casez`/`casex` use the same lowering
with `CaseMatch` conditions (`width = 1`, `mode = "casez"` or `"casex"`,
`left` and `right`); both operands retain whole-case sizing. Z is ignored
on either side, and `casex` also ignores X on either side. These conditions
enter `SelfCheck.SExpr.caseMatch`, not the M0 or symbolic expression loader.
Unqualified `case … inside` also uses this chain: scalar labels use `Binary`
`==?`, inclusive ranges use `>= && <=` (signed variants when appropriate),
and common-width fixed-array labels expand to their scalar elements. A guard
must return definite one to select its body; unknown guards advance the search.
Dollar case endpoints and array-element widening remain loud. These reuse the
existing membership helpers and do not extend the symbolic `Case` path.
`unique` case qualifiers remain explicit `CaseStatement:Unique` unsupported
members; see [the unique-case boundary](sv-unique-cases.md). The ordinary
case lowering has no unique-violation diagnostic channel.

Unsupported qualifiers and pattern forms,
effectful/nonintegral expressions and default-only cases retain
`CaseStatement:<reason>` refusals. A frontend error in such a compilation
adds top-level `CaseStatement:invalid-compilation`. This lowering does not
change symbolic `sv-0.2` `Case` nodes.

`Scanf` admits the integral `%b/%o/%h/%x/%d/%c/%s/%v` formats,
optional positive field width, suppression, whitespace, ordinary literals
and `%%`, with exactly one output per unsuppressed conversion. The input
is evaluated once. Successful outputs copy back left to right through the
existing packed-target machinery, resolving each selector after preceding
writes; unmatched outputs stay unchanged. The return count is assigned last.
Unknown packed input, literal mismatches requiring diagnostics, nonintegral
storage, effectful inputs/selectors, general strings, other call contexts
and symbolic mode remain loud. A frontend error adds
`Scanf:invalid-compilation` at design level.

An admitted fixed-size `$bits` query is a pure unevaluated leaf in this
source-tree check. Its argument subtree is skipped, not admitted as an
ordinary effectful expression.

| kind | key order / fields |
|---|---|
| `Block` | `kind`, `span`, `stmts`: [stmt...] — `begin ... end` (a single-statement body still nests one level: `"stmts": [<stmt>]`) |
| `BlockingAssign` | `kind`, `span`, `target` (`Ident`; legacy/self-check also `SelectTarget` or `ConcatTarget`), `value` (expr) — `=` |
| `Scanf` | legacy/self-check: `kind`, `span`, `input` (packed expression), `format` (literal string), `outputs` (source-ordered packed targets), `result` (packed target), `scanf_lowered: true` — direct blocking assignment of `$sscanf` |
| `SysCall` | legacy/self-check and scheduler: `kind`, `span`, `name` (`"$display"` \| `"$write"` \| `"$finish"` \| `"$stop"`), optional `format`, `args`, and parallel `arg_signed`; `$display`/`$write` use a literal format and integral arguments, `$finish`/`$stop` halt, and `$fatal` is represented as `$finish` with `fatal_task: true` and pure arguments evaluated before halting |
| `NonblockingAssign` | `kind`, `span`, `target` (`Ident`; legacy/self-check also `SelectTarget` or `ConcatTarget`), `value` (expr) — `<=` |
| `If` | `kind`, `span`, `cond` (expr), `then` (stmt), `else` (stmt \| `null`) — `else if` chains nest as `If` inside `else` |
| `For` | legacy/self-check: `kind`, `span`, `initializers` (statement array), `condition` (expr), `steps` (statement array), `body` (stmt) |
| `Repeat` | legacy/self-check: `kind`, `span`, `count` (expr), `count_signed` (Bool), `body` (stmt) |
| `Forever` | legacy/self-check: `kind`, `span`, `body` (stmt); ingestion uses existing `forLoop` with a true one-bit condition and empty initializer/step lists |
| `Delay` | scheduler: `kind`, `span`, `amount` (Nat below 2^64), `body` (stmt) — a known nonnegative integral-literal delay; ingestion retains the body after the delay checkpoint, and runtime refuses `amount == 0` because Inactive delivery is not in this tier |
| `WaitEvent` | scheduler: `kind`, `span`, `signal` (1-bit identifier), `edge` (`"posedge"`, `"negedge"`, or `"any"`) — a simple nested event wait; an enclosing `Block` retains the following body and the self-check runner refuses it |
| `Break` / `Continue` | legacy/self-check: `kind`, `span`; transfer to the nearest loop |
| `Unsupported` | see above |

The plain M0 cycle runner still accepts whole-signal identifier targets only;
a bit-select, part-select or concatenation LHS makes that *statement*
`Unsupported` (`AssignmentExpression:target`). The legacy/self-check extractor
also admits constant packed bit/part, concatenation-leaf and untagged
packed-member windows on continuous assignments, with static overlaps rejected
before execution; constant bit, simple part and indexed selections through
nested untagged packed-struct member chains use the same fixed-vector offsets,
also when the chain starts at a flattened fixed-array cell. Nested untagged
packed-union members use the same accumulated offsets and alias the flat base;
dynamic/effectful selections and tagged/unpacked aggregate members remain
unsupported. A
constant cell of an admitted one-dimensional
fixed-unpacked array is an ordinary `Ident` leaf, and constant packed
selections inside that cell use the same `SelectTarget`/`SelectRead` fixed-window
geometry. In the
legacy/self-check
extractor, a constant element of a one-dimensional fixed-unpacked integral
array is lowered
to an identifier cell such as `mem[2]`, and its declaration is expanded to one
vector `Var` per cell. Dynamic or out-of-range indices, multidimensional or
aggregate arrays, and whole-array operations remain loud except for the narrow
bounded dynamic access and whole-array positional-pattern assignments below.
`If` conditions may be any width (truthiness per LRM: true iff some bit is `1`).

The complete target admission and refusal rationale, including the current
corpus repricing, is recorded in [assignment targets](sv-assignment-targets.md).

Statement-position call effects and the residual call census are recorded in
[call statements](sv-call-statements.md).

Expression-position call effects and the residual call census are recorded in
[call expressions](sv-call-expressions.md).

The symbolic `sv-0.2` extractor uses the same flat cell representation for a
one-dimensional fixed-unpacked integral array: it emits one ordinary symbolic
`Var` for each declared index (`arr[0]`, `arr[1]`, ...), and a constant `arr[k]`
read or write becomes an `Ident` naming that cell. Dynamic or out-of-range
indices and nested-unpacked arrays stay `Unsupported`; the symbolic tier adds
no aggregate store or dynamic index executor.

An untagged plain packed integral typedef is also compile-time metadata in this
symbolic cell path. The extractor erases the alias, recovers the canonical
packed ranges for each emitted cell declaration, and keeps constant element
reads and writes as those same cell identifiers; unresolved, signed/2-state,
aggregate and dynamic alias forms remain `Unsupported`.

An ordinary four-state enum element type is likewise retained as a `TypeRef`
on each flattened cell. Enum members remain typed constant expressions, while
constant cell reads and writes use the same vector windows; signed, two-state
and aggregate enum storage remains outside this path.

An untagged packed struct or union element type is flattened to the same
fixed-width cell vector. A constant member access through that cell adds the
existing declaration offset and emits a `PartSel` window; tagged, nested-
unpacked and dynamic aggregate paths remain `Unsupported`.

An eligible cell-expanded declaration may also have an exact-length
assignment-pattern initializer; each element is converted once and stored in
its corresponding cell. Positional and elaborated keyed/default patterns are
admitted, as are replicated patterns whose constant count times their inner
element count equals the array length. Wrong-length, effectful or aggregate
initializers remain `Unsupported`.

The same representation admits an exact-length assignment-pattern statement to
an eligible cell-expanded array. Positional patterns and elaborated
keyed/default structured patterns lower to a `Block` of per-cell
`BlockingAssign` or `NonblockingAssign` nodes, in declared index order. A
replicated pattern is admitted when its constant repetition count times its
inner element count equals the array length. Each element must be a pure
integral expression and must not read the destination array, preserving the
source rule that the complete RHS is evaluated before any cell is updated.
Wrong-length, dynamic, aggregate and destination-aliasing patterns remain
`Unsupported`.

A fixed-size packed streaming source (`target = {<< [slice] {a, b, ...}}`
or the `>>` form) lowers to `Concat`. Right streaming retains source order
and ignores the slice size. Left streaming emits low chunks first using fixed
`SelectRead`/`PartSel` nodes; each chunk keeps its internal bit order, and the
final short high chunk keeps its actual width (IEEE 1800 §11.4.14.2). The
default left slice is one bit. A wider destination adds a trailing zero literal,
padding on the right under §11.4.14.3; destination two-state conversion follows
packing. Only pure admitted integral operands are accepted. A destination
smaller than the stream, nested streams, `with` selectors and unpacked
aggregate operands remain `Unsupported`. Symbolic parameter/generate families
also remain loud because this padding carries a fixed width.

A simple right-streaming unpack (`{>> {a, b, ...}} = source`) with no slice
size and direct integral identifier (including whole untagged packed structs
and unions), constant packed-member, fixed-array cell
or fixed-array cell-window targets reuses `ConcatTarget` (legacy) or its
symbolic window equivalent. The RHS must be at least as wide as the target
leaves. A wider source is sampled once and its leading target-width bits are
selected before the target split (IEEE 1800 §11.4.14.3): legacy mode uses a
`SelectRead` at the excess-width offset, symbolic mode a fixed `PartSel`.
Dynamic/effectful member or array selection, left streaming, nested or sized
streams, unpacked aggregates and a narrower source remain `Unsupported`.

In symbolic `sv-0.2` procedural and continuous assignments, the same
representation also admits constant packed bit/part leaves and constant cells
of a flattened one-dimensional fixed-unpacked integral array. These leaves are
fixed windows over ordinary vector state, so the RHS is sampled once and split
in source order by the existing comb executor. Dynamic or effectful array
indices, dynamic packed bounds, left/sized/nested streams and aggregate leaves
remain `Unsupported`.

An equal-length whole-array assignment from another eligible fixed-unpacked
integral array is lowered to the same per-cell block, pairing source and
destination cells in declaration order. Different lengths, incompatible
element widths, conditional aggregate expressions and unsupported storage
forms remain `Unsupported`.

An equal-length simple constant slice copy uses the same pairing for the
selected cells, including a whole-array source or destination on either side.
Overlapping self-copies remain `Unsupported` because the cell-expanded state
does not provide a temporary aggregate snapshot; dynamic, indexed and
out-of-range slices remain loud.

Equality and inequality of equal-length whole arrays or simple constant slices
are lowered to pairwise cell comparisons joined with logical `&&`. Unequal
shapes, aliasing forms and unsupported aggregate types remain `Unsupported`.
Case equality and inequality (`===`/`!==`) use the same lowering, preserving
exact x/z comparison through the existing scalar case operators.

An exact-length unpacked-array concatenation on the RHS of an eligible fixed
array assignment is flattened in operand order and lowered to the same per-cell
assignments. Scalar operands and existing whole-array/simple-slice operands are
accepted when their widths match; a source alias of the destination, dynamic
or aggregate operands, and mismatched lengths remain `Unsupported`. A typed
simple assignment-pattern operand is accepted when its one-dimensional fixed
array elements are pure integral values of the destination width; replication,
nested aggregates and mismatched pattern widths remain `Unsupported`.

A positional unpacked assignment-pattern LHS such as `U3'{a, b, c} = source`
is likewise lowered when its RHS is an eligible fixed-unpacked integral array
or simple constant slice and every pattern element is a distinct direct scalar
target. Each source cell is converted to its destination width and state kind
before the existing blocking or nonblocking assignment is emitted. Nested or
effectful pattern elements, duplicate targets, source/destination aliases and
aggregate or dynamic forms remain `Unsupported`.

An assignment whose RHS is a pure one-condition ternary over two eligible
fixed arrays is lowered cell by cell to `Ternary` values. The condition is
shared across the cells, so an x condition retains the ordinary per-bit
conditional merge. Conditional aggregate forms with patterns, calls, unequal
shapes or unsupported storage remain `Unsupported`.

The same lowering admits equal-length simple constant slices on the
destination and both branches. Overlapping source/destination array names are
rejected because the cell-expanded state has no aggregate snapshot; dynamic,
indexed and out-of-range slice forms remain `Unsupported`.

An exact-length positional pattern on a simple in-range constant slice of an
eligible fixed array is lowered to the selected cells in source order.
Elaborated keyed/default patterns and constant replicated patterns whose count
equals the slice length use the same lowering. Dynamic, indexed, out-of-range
and mismatched slice forms remain `Unsupported`.

For a one-dimensional fixed-unpacked integral array whose declaration has been
expanded to cells, a pure integral dynamic index is lowered to a finite
conditional over the declared cells. Dynamic writes become mutually exclusive
`If` branches; dynamic reads become a `Ternary` chain. Case-equality against
the declared index labels makes x/z indices and out-of-range indices perform
no write and read as all x. Associative, dynamic, queue, multidimensional and
effectful index forms remain `Unsupported`.

The symbolic `sv-0.2` tier also admits a continuous assignment whose LHS is a
nested concatenation of direct scalar, constant bit-select, or constant
part-select leaves. The extractor flattens nested concatenations into a
`ConcatTarget` in source order. `Design2` samples the RHS once and applies its
MSB-to-LSB slices to the existing packed-vector windows during comb settling;
aggregate storage and a second scheduler are not introduced. Empty, dynamic,
aggregate, duplicate, aliased, or effectful forms remain `Unsupported`.

A constant element of an admitted fixed-unpacked array is also a direct
`ConcatTarget` leaf after cell expansion. Its emitted `Ident` names the cell,
so source-order splitting and overlap checks use the same flat vector state;
dynamic element leaves remain `Unsupported`.

Packed selections applied after a constant array-cell select are normalized
against the cell's own packed declaration range. Thus a literal
`arr[0][10:9]` over a `[10:7]` element emits a `PartSel` over `arr[0]` with
zero-based offsets; dynamic or effectful packed bounds remain `Unsupported`.

The unpacked range itself may descend: emitted cell declarations follow source
declaration order (`arr[1]`, then `arr[0]` for `[1:0]`), while a constant label
still resolves to its own named cell. No ordinal-index rewrite is performed.

The same symbolic process representation carries a single constant `BitSel`
or `PartSel` target. Multiple such assignments settle in process order into
their existing vector windows, so disjoint partial drivers retain undriven
bits and update live when an input changes. Dynamic or effectful selections,
overlapping driver resolution, and legacy/self-check selected assignments
remain outside this surface.

Across separate symbolic continuous assignments, statically known windows on
the same base are checked for overlap after extraction. A duplicate or
overlapping constant driver is converted to `Unsupported` rather than being
silently resolved by process order; dynamic windows are not guessed.

Concatenation leaves may also be direct fixed members of an untagged packed
struct. Their accumulated offsets become ordinary `PartSel` leaves and retain
the one-sampled-RHS rule; `packed_member_concat` pins this form. Union-member
concatenations that overlap are rejected by the same guard.

A literal simple subrange of a packed member is flattened likewise: the
member offset and local slice offset are added before emitting the outer
`PartSel`. Dynamic member indices and non-simple nested selections remain
unsupported; `packed_member_subrange` pins the fixed case.

A literal bit-select of a packed member is flattened by adding the member's
fixed offset to the selected local bit offset and emitting a one-bit outer
`PartSel`. Dynamic member indices and non-simple nested selections remain
unsupported; `packed_member_bit` pins the fixed case.

The same fixed-window lowering applies to a literal subrange of a direct
untagged packed-union member. The union's alternate direct fields continue to
alias the one packed vector; `packed_union_subrange` pins this case. Tagged,
nested and dynamic union paths remain unsupported.

A literal bit-select of a direct untagged packed-union member uses the same
one-bit outer-vector window and aliasing rule; `packed_union_bit` pins the
case. Tagged, nested and dynamic union paths remain unsupported.

Literal indexed part-selects (`base +: width` and `base -: width`) of a direct
packed member are normalized to fixed outer-vector `PartSel` windows when the
member has a canonical packed range and the window is in bounds;
`packed_member_indexed` pins both directions. Dynamic, parameter-dependent,
noncanonical and effectful nested selections remain unsupported.

Direct untagged packed-union members use the same canonical indexed lowering
over their shared vector; `packed_union_indexed` pins both directions and
alternate-field aliasing. Tagged, nested, dynamic, parameter-dependent,
noncanonical and effectful union paths remain unsupported.

Literal simple subranges of packed members also normalize their declaration
labels to outer-vector offsets, including noncanonical member ranges when the
selected labels preserve the declared direction; `noncanonical_member_subrange`
pins this case. Direction-mismatched, dynamic, indexed and effectful nested
selections remain unsupported.

The same noncanonical label normalization applies to a direct packed-union
member and remains visible through its alternate field;
`noncanonical_union_subrange` pins that aliasing case. Direction-mismatched,
dynamic, indexed and effectful union paths remain unsupported.

Literal bit-selects of noncanonical packed members use the corresponding
zero-based declaration-label offset and emit a one-bit outer `PartSel`;
`noncanonical_member_bit` pins the accepted case. Dynamic and effectful
nested indices remain unsupported.

Direct noncanonical packed-union members use the same one-bit label mapping,
with the selected write visible through alternate fields;
`noncanonical_union_bit` pins the aliasing case. Dynamic and effectful union
indices remain unsupported.

An untagged packed-struct typedef is erased as compile-time metadata before
indexed member lowering, so its canonical field offsets use the same fixed
outer windows; `typedef_member_indexed` pins this spelling. Tagged, unresolved,
dynamic and effectful alias paths remain unsupported.

An untagged packed-union typedef is erased the same way, retaining shared-vector
aliasing for indexed member windows; `typedef_union_indexed` pins the alternate
field read. Tagged, unresolved, dynamic and effectful alias paths remain
unsupported.

Noncanonical simple subranges through an untagged packed-struct typedef retain
the declaration-label offset mapping after alias erasure;
`noncanonical_typedef_subrange` pins this case. Direction-mismatched, dynamic,
indexed and effectful alias paths remain unsupported.

The same noncanonical subrange mapping through an untagged packed-union typedef
retains alternate-field aliasing; `noncanonical_typedef_union_subrange` pins
the case. Direction-mismatched, dynamic, indexed and effectful union aliases
remain unsupported.

Nested untagged packed-struct chains accumulate each fixed declaration offset
before lowering a literal indexed selection of the final member;
`nested_member_indexed` pins the indexed case. Nested unions, direction
mismatches, dynamic and effectful paths remain unsupported.

The same accumulated offsets lower a literal bit-select of a final nested
member to a one-bit outer window; `nested_member_bit` pins the bit case. Nested
unions, dynamic and effectful paths remain unsupported.

For a noncanonical final member, the recursive chain offset and the local
declaration-label offset are both accumulated before emitting the outer slice;
`nested_noncanonical_subrange` pins this case. Direction mismatches, dynamic,
indexed and effectful paths remain unsupported.

Nested fixed member selections may also be concatenation leaves. Their
recursive windows retain one sampled RHS and source-order MSB-to-LSB splitting;
`nested_member_concat` pins this case. Dynamic, aliased, duplicate, overlapping
and effectful leaves remain unsupported.

The same recursive concatenation lowering applies through an untagged
packed-struct typedef after alias erasure; `typedef_nested_concat` pins the
metadata spelling. Tagged, unresolved, dynamic, duplicate, overlapping and
effectful alias leaves remain unsupported.

Nested concatenation leaves may use noncanonical final member ranges when their
literal labels follow the declaration direction. Recursive and local offsets
are combined before lowering; `nested_noncanonical_concat` pins this case.
Direction-mismatched, dynamic, duplicate, overlapping and effectful leaves
remain unsupported.

The same recursive and local offsets lower a literal bit-select of a
noncanonical final member to a one-bit outer window; `nested_noncanonical_bit`
pins the bit case. Dynamic and effectful paths remain unsupported.

Literal bit-selects through an untagged packed-struct typedef use the same
noncanonical declaration-label offsets after alias erasure;
`noncanonical_typedef_bit` pins the accepted case. Dynamic and effectful alias
indices remain unsupported.

The same noncanonical bit mapping through an untagged packed-union typedef
retains alternate-field aliasing; `noncanonical_typedef_union_bit` pins the
case. Dynamic and effectful union aliases remain unsupported.

The `bit_select_assign` fixture exercises two disjoint constant bit-select
drivers, including a selected read on the RHS and four-state propagation. It
uses the same `BitSel` window path; no separate scalar-driver representation
or scheduler is introduced.

An untagged packed-struct variable may use a direct integral member as a
constant window in the symbolic tier. An untagged packed union uses the same
single-vector representation, so an alternate field aliases the written
bits. The extractor lowers each direct member's fixed declaration offset to a
`PartSel` over the synthetic packed vector, so writes and reads use existing
storage. Tagged structs/unions, unpacked members and dynamic member paths
remain loud; nested untagged union chains use the recursive window rule below.
A typedef naming an untagged packed struct or union
is compile-time metadata and is skipped after its canonical vector width has
been checked; `packed_member_typedef` and `packed_union_typedef` pin those
cases.

Nested untagged packed-struct member chains are flattened in the same way:
the helper accumulates each declaration offset and emits one outer-vector
`PartSel`. `packed_member_nested` pins this chain; nested untagged packed-union
chains use the same outer offsets and alias guard. Other aggregate member
paths remain unsupported.

Literal indexed part-selects (`base +: width` and `base -: width`) are
normalized to ordinary constant `PartSel` bounds when the selected window is
in range. The legacy path also admits dynamic indexed slices over a nested
packed array when the selected width is a whole number of inner-element
chunks: the runtime outer label is scaled to the flat vector offset, with
ascending slices represented as increasing windows and descending slices using
the evaluator's high-endpoint convention. Dynamic or parameter-dependent bases
outside this packed shape and out-of-range windows remain `Unsupported`;
`indexed_part_assign` and `packed_array_dynamic_wide_slice` pin the accepted
forms.

For a literal simple part-select on a noncanonical packed range, the extractor
maps both source and destination labels to zero-based LVec offsets before
emitting `PartSel`. `noncanonical_part_assign` pins the `[10:3]` case; dynamic,
indexed and out-of-range forms remain loud.

Literal bit-selects on noncanonical packed ranges use the same mapping and
emit a zero-based `BitSel` index. Dynamic indices on those ranges remain
`Unsupported`, since the vector executor has no runtime declaration-range
metadata; `noncanonical_bit_assign` pins the accepted case.

## Expressions

The legacy/self-check blocking path additionally emits `SelectTarget` for
a packed bit or part destination. Its fields are `kind`, `span`, `width`,
`value` (an `Ident` base), `index` (an expression), `index_signed`,
`descending` and `two_state` (booleans). Simple parts use their low bound;
indexed-down parts use their high base and set `descending`. The bound
index retains its original width and signedness, and each destination
retains its own two-state conversion. This node is an assignment target,
not a readable expression.

For a one-dimensional packed scalar source with a noncanonical declared range,
the legacy extractor admits in-range constant bit selects, simple constant
part selects, and constant indexed part selects. It records the normalized
LVec offset of the selected bit or indexed base as a `Literal` index and
forces unsigned offset interpretation; `+:` retains `descending = false` and
`-:` retains `descending = true`. Dynamic/effectful bases and out-of-range
windows remain `Unsupported`.

Direct fields of an untagged packed struct or packed union are represented by
the same window nodes: the field's fixed `bitOffset` becomes a literal LVec
index over the aggregate identifier. A chain through nested untagged packed
structs or unions is flattened to the outer aggregate's fixed bit offset;
alternate union members alias that base and static overlap remains loud.
Unpacked struct/union fields, classes, interfaces and tagged unions remain
unsupported.

`ConcatTarget` has `kind`, `span`, `width` and `parts` (source-ordered
targets), with nested `ConcatTarget` nodes retained. Whole `Ident` leaves
add a `two_state` boolean; selected leaves retain the fields above.
Ingestion flattens nested concatenations to width-bearing `PackedTarget`
leaves and checks every recorded aggregate width. RHS slices are assigned
from the low end of the rightmost leaf. `AssignmentOrder` is an evaluator
parameter, not an extractor field or a compiler-selected order; the named
default is right-to-left. The RHS is captured once, and each index is
evaluated against the then-current frame at its chosen destination step.
An order must be a permutation of all leaf indices, or execution refuses.

Selected nonblocking targets use the same `SelectTarget` shape in the
legacy/self-check surface. The RHS and index are sampled against the active
state; the queue records a full-value snapshot derived from the last pending
snapshot for that signal, preserving disjoint merges and issue order at
commit. Concatenated nonblocking targets use `ConcatTarget` and flatten to
the same ordered `PackedTarget` leaves as blocking concatenations. Nested
targets retain their envelope shape, while the self-check parser flattens
them for queue insertion. Invalid compilations containing an admitted target
retain `SelectTarget:invalid-compilation` or
`ConcatTarget:invalid-compilation`. Partly out-of-range writes follow the
per-bit rule in the value primitive, with simulator disagreements kept as
diagnostics rather than hidden by a second semantic path.

The legacy/self-check vocabulary also includes `BitQuery` for IEEE
1800-2023 §20.9. Its fields are `kind`, `span`, `width`, `op`, `operand`
and `controls` (an expression array). `op` is `$countbits`, `$countones`,
`$onehot`, `$onehot0` or `$isunknown`; only `$countbits` has controls,
with at least one. Controls retain their original widths: evaluation
uses each least-significant bit and ignores repeated control values when
counting positions. The operand is not widened to the result's width.
The two count functions have `width: 32` and `signed: true`; predicates
have `width: 1` and unsigned results. The current admission is integral
and effect-free; the symbolic `sv-0.2` vocabulary is unchanged.

Every supported expression node carries `width`: its **elaborated result width
in bits**. (`Unsupported` expression nodes have no `width`.)

| kind | key order / fields | width invariant |
|---|---|---|
| `Ident` | `kind`, `span`, `width`, `name` (string) | declared width of the named var/net/port |
| `Literal` | `kind`, `span`, `width`, `bits` (string), optional `signed`, `fixed_bits_query`, `fixed_clog2`, `fixed_dimension_query` provenance | `len(bits) == width` |
| `Unary` | `kind`, `span`, `width`, `op` (`"~"` \| `"!"` \| `"+"` \| `"-"`), `operand` (expr) | `~`,`+`,`-`: `width == operand.width`; `!`: `width == 1` |
| `Reduce` | `kind`, `span`, `width`, `op` (`"|"` \| `"&"` \| `"^"` \| `"~|"` \| `"~&"` \| `"~^"`), `operand` (expr) | `width == 1`; operand is any admitted integral expression |
| `Binary` | `kind`, `span`, `width`, `op` (see below), `left`, `right` (exprs) | arithmetic/bitwise operators: common-width children; shifts: `width == left.width`, with a self-determined right operand; comparisons: `width == 1` and equal child widths |
| `Ternary` | `kind`, `span`, `width`, `cond`, `then`, `else` (exprs) | `width == then.width == else.width`; `cond` any width |

`<<` `>>` `<<<` and `>>>` are integral shifts (§11.4.10). Their envelope
operators are typed as `u<<`/`s<<`, `u>>`/`s>>`, `u<<<`/`s<<<`, and
`u>>>`/`s>>>`; the prefix records the signedness of the left operand.
The right operand is always unsigned and self-determined. The result width
is the left operand width, including assignment-context widening before the
shift and destination narrowing after it. Unknown shift amounts produce all
x; overshifts zero-fill, except signed `>>>`, which sign-fills.

`==`/`!=` are *logical* equality. `===`/`!==` are *case* equality: they
compare every four-state bit exactly and always produce a definite one-bit
result. The width invariants hold

Whole values of an admitted shallow untagged unpacked union are emitted as
`Ident` expressions naming their shared vector cell for these equality forms;
union arithmetic remains unsupported.

`Ternary` likewise admits two equal-shape whole-union arms and uses their
shared vector-cell width; mixed-shape and aggregate arms remain unsupported.
whenever the children are supported nodes — the extractor enforces them and
demotes violators to `Unsupported`; if a child is itself `Unsupported` its
width is unknown and the parent keeps its structure (the interpreter goes
`.unsupported` on reaching the child).

Logical `&&`/`||` also produce a one-bit result. Each operand is converted by
the four-state truthiness rule before the logical table is applied; they are
not bitwise aliases for `&`/`|`.

Wildcard `==?`/`!=?` produce an unsigned, one-bit self-determined result.
Right x/z positions match every left value; all other positions use logical
equality. A definite mismatch dominates an unknown cared-left position.
Both operand widths agree after the elaborated conversions. Surrounding
assignment or arithmetic context widens the result after the comparison,
while its operands retain their own width and signedness. The same spellings
are retained in symbolic `sv-0.2` expressions.

Unary reductions `|`, `&`, `^`, `~|`, `~&` and `~^` produce one-bit values.
The first three fold the operand's bits with the corresponding four-state
table; the last three negate those results. Unknown bits remain `x` unless a
definite table result decides the fold (`|4'b100x` is `1`, while `&4'b111x`
and `^4'b101x` are `x`).

Unary `+` remains a `Unary` node through extraction and symbolic sizing.
IEEE 1800-2023 §11.4.3 requires the arithmetic x/z rule: a fully known
operand is unchanged, while any x/z bit makes the entire result x. The
shared `LVec.pos` rule applies after context sizing, including when the
unary expression occurs inside another arithmetic operand.

Runtime integral division uses `u/` for unsigned operands and `s/` when
both elaborated operands are signed. Zero divisors and x/z operands give
all x; known signed quotients truncate toward zero at the common width.
Plain scalar `/=` lowers to the same operator. Symbolic constant positions
retain `/` for integer elaboration, while runtime vector division retains
typed operators and unfolded `Resize`/`SignedResize` operands. Instantiation
recomputes their context widths, including signed constants, without
widening self-determined Boolean operands or ternary conditions. Real
division and selected compound targets stay loud. See `docs/sv-division.md`.

Runtime integral remainder uses `u%` for unsigned operands and `s%` when
both elaborated operands are signed. Zero divisors and x/z operands give all
x; signed remainders follow truncation-toward-zero division and therefore
the dividend's sign. Plain scalar `%=` uses the same typed operator. Constant
symbolic positions retain `%` for integer elaboration; runtime vector
remainder retains the typed operators and the same context-width conversion
rules as division. Real remainder and selected compound targets stay loud.
See `docs/sv-remainder.md`.

Integral `*` uses the same elaborated common-width invariant as `+` and
`-`. Operand `Resize`/`SignedResize` nodes act before multiplication;
destination narrowing acts after it. A four-state unknown in either
operand makes the entire product unknown. Plain scalar `*=` lowers to a
`Binary *` reading the original target, while selected compound targets
stay loud. `Multiplication:invalid-compilation` prevents a frontend error
elsewhere in a product-containing module from being silently discarded.
In sv-0.2, constant multiplication still elaborates to an integer literal;
nonconstant multiplication instantiates the runtime `.mul` operator.

The extractor transparently unwraps slang's **same-width implicit/propagated
conversions** (elaboration artifacts: 2-state literal into a 4-state context,
sign reinterpretation) — they never appear in the envelope. *Width-changing*
implicit conversions are the M0 "width mismatch in source" case ⇒
`ConversionExpression:width`.

### `Literal` — 4-state constants

The legacy/self-check extractor also folds a pure constant `$clog2` call
(IEEE 1800-2023 §20.8.1) to a signed 32-bit `Literal`. Such a literal carries
`fixed_clog2: true` provenance. The bound argument must be one integral,
effect-free expression that slang has evaluated during elaboration; zero and
one produce zero, and the argument is treated as unsigned, so a 32-bit `-1`
produces 32. The argument must be fully known. Other pure integral calls
use the runtime `Clog2` node described below; unknown arguments refuse during
evaluation. Effectful, malformed and nonintegral calls remain `Unsupported`.
A frontend error or declaration-redefinition conflict in a compilation
containing an admitted call adds `$clog2:invalid-compilation`.

It also folds `$size`, `$high`, `$left`, `$right`, `$low`, `$increment`,
`$dimensions` and `$unpacked_dimensions` for fixed integral types and fixed
arrays thereof (array-query system functions, §20.7). The result is a signed
32-bit `Literal` carrying `fixed_dimension_query` with the query name;
dimensions are numbered from one, unpacked before packed, retaining each
declared left/right bound. A predefined integer, enum or packed aggregate
contributes its implicit packed bit dimension; a plain scalar contributes none.
Tagged unions are outside this dimension-query slice. `$size` is
`abs(left - right) + 1`, `$high`/`$low` select the larger/smaller bound,
and `$increment` is one for descending or equal bounds and minus one for
ascending bounds. The count queries return total and unpacked dimension counts.
The six bound/size/direction queries accept an optional pure, frontend-bound
constant dimension selector, defaulting to one. Literal and parameter/enum
leaves do not need a cached evaluation; other unbound compound selectors stay
loud without invoking an evaluation context. Runtime or invalid selectors,
dynamic/associative/queue arrays, effectful operands, malformed calls and
nonintegral element types remain `Unsupported`, with
`DimensionQuery:invalid-compilation` retained for an admitted query in an
otherwise erroneous compilation.

The legacy/self-check extractor also emits signed 32-bit `Literal` nodes
for `$bits(expression)` or `$bits(data_type)` with fixed-size bitstream
arguments (IEEE 1800-2023 §20.6.2). Their `bits` encode the bound type's
`bitstreamWidth` modulo `2^32`, with `signed: true` and optional provenance
`fixed_bits_query: true`. The argument is not evaluated or converted;
fixed-size bitstream operands remain eligible even when their source syntax
contains a call, assignment,
increment, decrement, or selected read. Context resizing retains this query
literal rather than folding away its admission evidence. Dynamically sized and
non-bitstream arguments remain `Unsupported` (apart from the existing empty
dynamic-array/string metadata cases); a frontend error in a compilation
containing an admitted query adds top-level `$bits:invalid-compilation`.
Existing literal ingesters require no new constructor, and symbolic `sv-0.2`
`SysCall` queries are unchanged.

A zero-argument `$time` expression in the time-zero self-check slice is also
folded to a 64-bit all-zero `Literal` with `time_zero: true` provenance. The
self-check runner has no elapsed time; delays, event waits, `$realtime` and
malformed `$time` calls remain loud. This uses the existing `Literal` node and
does not add a scheduler rule.

```json
{"kind": "Literal", "span": {...}, "width": 8, "bits": "1x0z1010"}
```

`bits` is a string over `{'0','1','x','z'}` (lowercase), length exactly
`width`, written **MSB-first** — the same order as SV source and `$display %b`
output: `8'b1x0z_1010` ⇒ `"1x0z1010"`, `8'd2` ⇒ `"00000010"`, `'0` in an 8-bit
context ⇒ `"00000000"`, `'1` ⇒ `"11111111"`, `'x` ⇒ `"xxxxxxxx"`.

> **Ingester warning — bit order.** `LeanModels.Sv.LVec` is **LSB-first**
> (`bits[0]` is bit 0). `bits` here is MSB-first, so the ingester must
> **reverse the string**: `LVec.bits[i] = bits[width - 1 - i]`. This is the
> one place the envelope and the Lean value core differ in orientation.

x/z digits are preserved exactly as written (after slang's per-digit
expansion, e.g. `8'bx` ⇒ `"xxxxxxxx"` per the LRM's leading-digit extension
rule). Unsized bare integers (`1`, which is a signed 32-bit `int`) only occur
behind width-changing conversions in M0 code and therefore surface as
`Unsupported` unless the context is exactly 32 bits wide.

module adder (input  logic [7:0] a, b,
              output logic [7:0] s);

# Symbolic mode — schema sv-0.2 (additive; `--top`)

Phase 1 of the CV32E40P program adds a second extraction mode:

```
python3.12 extractors/sv/extract.py --top <module> <files...> [-I <incdir>] [-o out.json]
```

All sources are compiled as **one** slang compilation (multi-file is for
**name resolution only**: package imports, typedefs, enum types) and exactly
the named top module is emitted, as one envelope (default output path: next
to the file that defines the top module, `<file>.sv.json`). Everything in
this section is **additive**: single-file mode (`--top` absent) is untouched
and remains byte-identical at schema `sv-0.1`.

Two design laws govern this mode (they are the point of the program):

1. **Parameters stay symbolic.** Parameter *values* are never folded into
   the envelope's primary form. A parameter reference in any expression
   position is a `ParamRef` node; declared widths are the source's symbolic
   range expressions. On the Lean side (phase 2) a parameterized module
   becomes a Design-valued *function* of its parameters, enabling ∀-width
   theorems.
2. **Generate stays structural.** A generate-for is ONE `GenerateFor` node
   (genvar, symbolic header expressions, body template) — an indexed family
   the prover handles by induction; a generate-if is ONE `GenerateIf` with a
   symbolic condition. Nothing is unrolled.

**Symbolic-primary / resolved-secondary convention.** Wherever slang only
exposes post-elaboration integers, the envelope carries the recovered
symbolic form as the primary field and the defaults-elaborated integer in a
`resolved`-family field beside it, for phase-2 cross-checks only:
`resolved` = elaborated *value* (on `ParameterDecl`/`LocalParam`/`SysCall`),
or elaborated *bit width* (on `PackedType`/`TypeRef`); `resolved_width` =
elaborated context width (on `Int`/`Fill`); `resolved_count` = number of
elaborated instances (on `GenerateFor`). Ingesters MUST treat these as
metadata, never as the contract.

**Recovery method and honest limits.** (a) Bound expressions are used
wherever slang retains them — parameter/localparam initializers
(`ParameterSymbol.initializer`), generate-for headers
(`initialExpression`/`stopExpression`/`iterExpression`), generate-if
conditions (`conditionExpression`), and every process/assign expression;
in these trees parameter references are still symbol references, emitted as
`ParamRef`/`GenvarRef`/`EnumRef`. (b) The one place slang folds without
keeping a bound expression is the packed **dimensions of declared types**
(resolved to integer ranges); those are recovered from the declaration's
*syntax tree* and identifiers in them are classified via `lookupName` on the
top module's body scope. Limits: syntax-recovered nodes carry `"width":
null` (they are not re-type-checked); a dimension identifier not visible
from the top module's scope (e.g. a package-private name never imported)
degrades to an `Unsupported` node with the `resolved` width still present
(`"packed": null` when a whole dimension list is unrecoverable); genvar
references are recognized *by name* against the enclosing generate stack;
`width` fields on ordinary expression nodes inside processes are elaborated
under **default** parameter values (cross-check only — the binding symbolic
widths are on the declarations); the body template of a `GenerateFor` is
bound from its first elaborated instance (a loop with zero instances under
defaults keeps its body as one `Unsupported` node with the source text);
untaken generate-if branches ARE emitted (slang binds them in
uninstantiated mode).

## Envelope (symbolic)

Top-level key order: `schema_version` (`"sv-0.2"`), `language`, `frontend`,
`mode` (`"symbolic"`), `top`, `source_files` (list of `{path, sha256}` in
CLI order), `packages` (sorted names of packages the top module actually
references), `design`, `lean_blocks`. `design.modules` holds exactly one
`Module`; `design.others` is `[]` (packages are name-resolution inputs, not
`$unit` noise).

Symbolic-mode changes to existing nodes: `Port`/`Var`/`Net` carry their
declared type object (`PackedType` or `TypeRef`) in the `width` field
(instead of an integer); enum-typed ports/vars/idents are in-vocabulary;
multi-dimensional packed vectors of 4-state unsigned scalars are
in-vocabulary (`packed` lists one `{msb, lsb}` per dimension, outermost
first). In **symbolic expression positions only** (parameter defaults,
localparam exprs, generate headers and conditions, dimension bounds) the
operator set additionally admits `* / % ** << >> <<< >>>`; in ordinary
process/assign positions the M0/self-check operator set is unchanged and
everything else remains `Unsupported` (selects, case, event lists,
instantiations, 2-state types, ... — phase 2+ tiers). A width-changing
implicit conversion whose operand contains symbolic references is emitted
as `Resize` around the symbolic operand (unsigned operands; signed →
`Unsupported`) instead of being constant-folded.

New `Unsupported` tags of this mode: `Syntax:<SyntaxKind>` /
`Syntax:Identifier:unresolved` / `Syntax:Identifier:<SymbolClass>`
(dimension-syntax recovery), `GenerateBlockSymbol:unconditional` (bare
`begin`/`end` generate block), `GenerateFor:no-template` (zero-instance
loop body), `TransparentMemberSymbol:<Class>`.

## Self-check signed integral tier (2026-10-09)

The elaborated self-check surface admits signed scalar and descending
zero-based packed-vector variables, plus `byte`, `shortint`, `int`,
`longint`, `integer` and `time`, including their unsigned variants.
Widths and two-/four-state initialization follow the bound frontend
type. Signed `Var`, `LocalDecl` and `Ident` nodes carry an optional
`signed: true` field for auditability. Runtime storage remains a bit
vector: signed relational operations are encoded as `s<`, `s<=`, `s>`
and `s>=` after context propagation, not inferred from variable names.

`SignedResize` has `kind`, `span`, `width` and `operand`. It retains the
low `width` bits when narrowing and copies the source's most significant
bit when widening, including `x` and `z`. For an implicit conversion,
the source and propagated result types must both be signed; an unsigned
context uses the existing zero-filling `Resize`. In particular,
assignment to an unsigned wider destination can contain an inner signed
extension followed by a
same-width unsigned reinterpretation, while mixed-sign arithmetic and
comparison can propagate an unsigned widening context. Conversion
placement in the expression tree is significant.

The self-check compiler lowers `SignedResize` to the shared
`LVec.resizeSigned` value rule. Non-suspending statement execution uses
the existing `stepSStmt_done_agrees` correspondence, not another
scheduler. Known signed decimal output uses the two's-complement integer
and the existing natural field-width rule; unknown output retains the
existing `x`/`X` rendering.

The legacy M0 envelope now also admits signed four-state ports, variables and
nets. Their declarations and identifier nodes carry optional `signed: true`
metadata; signed order comparisons use the `s<`/`s<=`/`s>`/`s>=` operator
tags and the shared two's-complement value rule. Symbolic signed resizing is
still loud. Enums, structures, unpacked arrays, reversed packed ranges and
unsupported operators remain loud in this surface.

## Integral explicit conversions (2026-10-09)

An elaborated `ConversionExpression:Explicit` whose source and result
both have admitted integral type shapes lowers to the same existing
expression nodes on the legacy/self-check path. Scalar, predefined
integer and descending `[W-1:0]` packed scalar types are admitted;
symbolic extraction continues to refuse explicit conversions.

The cast operand is self-determined. A width change lowers to
`SignedResize` when the **source type** is signed, otherwise `Resize`,
regardless of the result type's signedness. An equal-width conversion
keeps the operand unchanged. If the source is four-state and the result
is two-state, an outer `Squash2` maps `x`/`z` to zero at the result width.
Signing casts therefore need no extra runtime node: slang's elaborated
result type already determines the signedness of later consumers and
of any enclosing implicit conversion.

Nonintegral and exotic integral type shapes remain
`Unsupported` with `sv_kind = "ConversionExpression:Explicit"`.
Bitstream and streaming-concatenation conversion kinds retain their
own refusals. This lowering changes neither the self-check parser nor
the scheduler vocabulary.

## Integral signing functions (2026-10-11)

The legacy/self-check path admits the IEEE 1800-2023 §11.7.1 / §20.5
system functions `$signed` and `$unsigned` with one admitted integral
operand. The bound argument and result must have equal bit widths and
the same two-state/four-state classification. Selected integral operands
retain their packed value width even when the selected source range does
not start at zero. The operand's expression node is retained unchanged
at runtime; its optional `signed` metadata is replaced by the function's
result signedness and `signing_cast` records the function name. Its span
covers the call. No new executable expression kind is introduced.

Signedness is consumed from the frontend's elaborated types: subsequent
implicit conversions choose `SignedResize` or `Resize`, comparisons
choose signed or unsigned operators, and output tasks retain the result's
signed decimal interpretation. A surrounding mixed-sign expression can
demand zero extension even when the call itself is `$signed`. The function
does not inherit an enclosing assignment's width; argument evaluation is
self-determined. Four-state bits are preserved until an actual two-state
destination conversion applies `Squash2`.

Pure signing calls also participate in ordinary case statements, selected
assignments and fixed-size `$bits` queries. Unsupported operands, side
effects and invalid signatures remain loud. Constant folding cannot erase
signing-call admission evidence; an erroneous compilation containing an
admitted call retains `SigningCast:invalid-compilation`. Symbolic `sv-0.2`
calls keep their existing `Cast` representation and admission boundary.

## Integral typedef declarations (2026-10-09)

On the legacy path, a bound `TypeAlias` member at module or compilation-unit
scope is omitted when its bound declared type passes `type_width_2s` or
the fixed dimension-query metadata admission: scalar, predefined integer,
enum, packed structure or untagged packed union, including fixed packed and
unpacked arrays thereof. The frontend has already
resolved alias uses, including alias chains, so existing variable and
expression nodes carry the resulting width, signedness and state kind.
No `TypeAlias` runtime node is introduced. Block-local typedefs are
elaboration-only in the bound statement tree, with variable declarations
lowered through the original runtime canonical type check. Erasing a type
alias does not admit runtime aggregate or unpacked-array storage.
Frontend errors in a compilation containing an erased alias retain
`TypeAlias:invalid-compilation` rather than disappearing with the declaration.

Unsupported module aliases retain `sv_kind = "TypeAliasType:TypeAlias"`;
unsupported compilation-unit aliases retain `sv_kind = "TypeAliasType"`.
Dynamic storage, tagged unions and nonintegral element types remain outside
this metadata admission. Symbolic integral aliases
retain their existing refusal; symbolic enum metadata is unchanged.
Runtime compilation-unit members are not erased or admitted by this rule.

## Four-state selected reads (2026-10-09)

The legacy `SelectRead` node has `kind`, `span`, `width`, `value`,
`index`, `index_signed` and `descending`. The source must be an admitted
four-state predefined integer or descending `[W-1:0]` packed scalar
vector. The selector must have an admitted integral type; its signedness
is explicit because interpreting a negative signed index as an unsigned
natural would change an indexed slice that overlaps bit zero.

For bit reads, `width` is one and `descending` is false. For a constant
part read, `index` is the bound right endpoint and `width` is the bound
result width. Indexed-up reads use the left/base operand and false;
indexed-down reads use the left/base operand and true. The evaluator
computes the low index as `index - width + 1` for descending reads, else
`index`, in integer arithmetic. It reads low-to-high into the existing
LSB-first vector, supplying `x` only for individual invalid positions.
An unknown selector returns an all-x result of the bound width.

Result signedness is unsigned, with enclosing elaborated conversions
retained by ordinary lowering. Two-state, scalar and unsupported source
shapes remain `Unsupported` with `:source-type`; unsupported selector
types retain `:index-type`. Symbolic `BitSel`/`PartSel` nodes are unchanged;
`SelectRead` does not admit selected assignment targets.
A legacy design containing `SelectRead` and any frontend error diagnostic
also carries `SelectRead:invalid-compilation` in its top-level refusals;
recovering a typed expression from malformed source is not admission.


### Time-zero literal provenance

A legacy `Literal` may carry `"time_zero": true` when it represents the
zero-argument `$time` query within the time-zero self-check tier. Ingestion
retains the presence of any such literal, including nested expressions and
initializers, as `SelfCheck.Design.requiresTimeZero`. `runSelfCheck` may
evaluate it; `elabTimedDesign` rejects the design before creating a timed
world. An ordinary zero literal carries no restriction. The existing marker
is admission metadata and does not define a dynamic clock query.

### Explicit plusarg input queries

Legacy `TestPlusargs` expressions carry `format` (the literal query),
`width = 32`, `signed = true` and `plusargs_lowered = true`.
`ValuePlusargs` statements carry a literal integral `format`, a packed
`target`, and a generated identifier `result`. Their original expression
context lowers to ordinary `Block`, `If`, `LocalDecl` and assignment nodes,
retaining short-circuit placement. Generated declarations carry
`automatic_plusargs = true` and use collision-checked `$plusargs:` names.
`ValuePlusargsExpr` is an internal conversion marker; unsupported placements
become `Unsupported` before an envelope is emitted.

The loader requires an explicit ordered list of plusarg contents without
leading `+`. It specializes pure queries to literals and stateful queries to
existing packed copyback plus return assignments. A miss emits only the return
assignment. Missing inputs or unsupported conversion observations refuse
loading. A compilation with frontend errors and any admitted query also
retains `Plusargs:invalid-compilation`. See [the contract](sv-plusargs.md).


## Blocking intra-assignment controls

In legacy mode, an admitted blocking assignment with intra-assignment timing
lowers to a `Block` marked `intra_assignment_lowered = true`. Its statements
are a `LocalDecl`, the existing wait, and a `BlockingAssign` with a singleton
`ConcatTarget`. The local has `automatic_intra = true`, four-state storage,
the elaborated destination width, the RHS initializer, and a collision-checked
`$intra:<source-offset>` name. The copyback reads that local. Destination
selectors remain solely in the final target and execute after resumption.
The local executes afresh on each visit; loop lifetime checks recognize it.

Waits use `Delay` with an empty body, `WaitEvent`, or `Repeat` with explicit
`count_signed` and a `WaitEvent` body. Repeated counts use the existing sampled
loop semantics. There is no new Lean statement or scheduling primitive.
`Delay 0` remains represented and the timed slot retains its explicit
Inactive-delivery refusal. Internal procedural clock publication and timed
`$time` retain their existing runtime guards.

Nonblocking controls, unsupported destinations, effects, delay/event forms
and symbolic mode carry `IntraAssignment:<reason>` or the shared timing
refusal tag. Any invalid compilation containing this lowering also receives
`IntraAssignment:invalid-compilation`. See [the contract](sv-intra-assignment.md).

In particular, `IntraAssignment:publication-or-context` remains explicit for
nonblocking intra-assignment controls. Its future publication and same-time
ordering are not represented by the blocking capture/wait lowering, so the
envelope does not fabricate a sleeping process or an update queue.

Random sequence productions remain explicit `RandSequenceStatement` unsupported
members. The envelope carries no production graph, constrained-random state or
generated automatic action frame, so alternatives, repeats, weights,
conditionals and action blocks are not lowered into procedural statements.
See [the randsequence boundary](sv-randsequence.md).

`RandCaseStatement` remains explicit as a weighted-random branch boundary;
see [the randcase boundary](sv-randcase.md). The envelope has no sampled
weight vector, random oracle or weighted-selection trace, so no branch is
lowered by fixed seed or source order.

`DisableStatement` remains a named-scope cancellation boundary; it has no
target-scope identity or cancellation continuation. The envelope therefore
does not lower a disable to `break`, return or silent child cancellation.
See [the disable boundary](sv-disable.md).

`SpecifyBlockSymbol:SpecifyBlock` remains explicit as a structural timing-model
boundary. The envelope has no path-delay graph, timing-check monitor, pulse
state or notifier publication, so specify declarations are not lowered to
procedural statements or a fixed delay. See [the specify boundary](sv-specify.md).

`NetAliasSymbol:NetAlias` remains explicit as a bidirectional net-topology
boundary. The envelope has no alias graph or resolved-driver topology, so an
alias is not lowered to a one-way assignment or an initial copy. See [the
net-alias boundary](sv-net-alias.md).

`Package:initializer` remains explicit as a package initialization-order
boundary. The envelope has no dependency graph or initialization phase for
runtime package-variable reads, so these initializers are not folded to
constants, dropped or run as module processes. See [the package-initializer
boundary](sv-package-initializers.md).

`TimedStatement:EventListControl` remains explicit as a multi-event wait
boundary. The envelope has no multi-event registration, per-event `iff` guard
or retained rearming state, so event lists are not lowered to one signal or a
fixed sequence. See [the event-list boundary](sv-event-lists.md).

`ClockingBlockSymbol:ClockingBlock` remains explicit as a scheduler-region
synchronization boundary. The envelope has no clockvar sample/drive queues,
skew representation or Preponed/Reactive bridge, so a clocking block is not
lowered to an ordinary event wait or variable declaration. See [the
clocking-block boundary](sv-clocking-blocks.md).

`Package:invalid-compilation` remains explicit as a design-level diagnostic
boundary. The envelope has no package diagnostic provenance or partial-
elaboration contract, so a rejected package is not salvaged by dropping its
imports or declarations. See [the invalid-package boundary](sv-package-invalid.md).

`ProceduralAssignStatement` remains explicit as a retained-driver boundary.
The envelope has no procedural-driver identity, RHS sensitivity set,
force/release priority or net-resolution restoration state, so procedural
`assign`/`deassign` and `force`/`release` statements are not rewritten as
ordinary blocking assignments. See [the procedural assign boundary](sv-procedural-assign.md).

`DefParamSymbol:DefParam` remains explicit as a hierarchy-elaboration
boundary. The envelope has no instance-path parameter environment, override
precedence or parameter-before-generate state, so a defparam is not folded to
a local constant or rewritten as an inline instance assignment. See [the
defparam boundary](sv-defparam.md).

`NetSymbol:delay` remains explicit as a scheduler-facing publication
boundary. The envelope has no delayed net driver, transition queue,
rise/fall/turn-off selector or inertial cancellation state, so net and
declaration-time continuous-assignment delays are not rewritten as immediate
assignments. See [the net-delay boundary](sv-net-delays.md).

`ContinuousAssignSymbol:delay` remains explicit as a delayed-driver boundary.
The envelope has no pending continuous-assignment event, transition selector
or inertial cancellation state, so `assign #d` is not rewritten as an
immediate assignment. See [the continuous-assignment delay boundary](sv-continuous-assign-delays.md).

`TimedStatement:DelayControl:expression` remains explicit as a dynamic-delay
boundary. The envelope has no runtime delay evaluator, timeunit/precision
environment or X/Z conversion rule, so an expression delay is not folded to a
fixed literal. See [the dynamic delay-expression boundary](sv-delay-expressions.md).

### Legacy elaborated scope provenance

In `sv-0.1`, live generate scopes flatten into ordinary module declarations
and processes. Each such node carries `generated_scope`, a structural route
of member ordinals, labels and loop-entry indices. Bound names use injective
`$generate:` storage identities; repeated locals and source-offset temporaries
retain their scope. The module carries `elaboration_lowered: true`; folded
integral module/local/genvar parameter literals and admitted bound hierarchical
references carry the same marker. Source genvars allocate no runtime slot.
Inactive branches and zero-count loops emit no runtime nodes. Unsupported
active members, invalid compilations, dependent static initialization and
expansion-limit violations remain loud. The symbolic schema keeps its existing
parameter/generate nodes. See [the contract](sv-elaborated-generate.md).


### Legacy integral assignment-pattern provenance

Admitted positional, structured and constant-replicated integral patterns
become ordinary `Concat` expressions with `assignment_pattern_lowered: true`
and `source_pattern` (the original frontend pattern kind). Parts retain
bound element conversions and declared packing order. Numeric-index keyed
inventories are reordered for descending declarations; existing fixed-array
cell lowerings use the same correspondence helper. Source effects, invalid
compilations, unsupported shapes and expansion-limit violations remain loud.
The symbolic schema's packed-pattern admission is unchanged. See
[the contract](sv-assignment-patterns.md).

Pure self-determined integral replication lowers to ordinary `Concat` with

`unsized_based_widening: true`; affected elaboration constants refuse.
Symbolic `Repl` remains unchanged. See [the contract](sv-replication.md).


### Legacy runtime ceiling logarithm

`Clog2` has `kind`, `span`, `width: 32`, `signed: true`, `operand` and
`runtime_clog2: true`. The operand retains its own integral width. The loader
checks the signed 32-bit result shape; the evaluator reads the operand once
and reuses `LeanModels.Sv.clog2` on its unsigned finite-vector value. Unknown
bits refuse. Existing correct `fixed_clog2` literal folding remains; affected
unknown elaboration constants refuse rather than use a frontend approximation.
Symbolic `SysCall` is unchanged. See [the contract](sv-runtime-clog2.md).

### Legacy selected operator assignments

Operator assignments lower to ordinary blocking assignments and scoped
`LocalDecl` captures, marked `automatic_compound: true`. New lowering roots
carry `compound_assignment_lowered: true`. Captured addresses and array
results are evaluated before copyback; bounded packed-member temporaries
prevent writes to adjacent fields. No new scheduler statement is introduced.

`CompoundRead` has `kind`, `span`, positive `width`, `value`, `index`,
`index_signed` and `descending`, matching `SelectRead`'s geometry. It reads
the current vector and captured index once. An overlapping, partially
out-of-range interval refuses as `AssignmentExpression:compound-partial-range`;
otherwise it delegates to `selectedRead`. Unknown or wholly out-of-range
targets still evaluate the complete RHS before an ordinary no-store copyback.
The complete frontend-bound RMW tree retains every conversion around this
read. Previously correct scalar envelopes are unchanged. Symbolic compounds
remain loud. See [the contract](sv-compound-assignments.md).

## Min typ max

In `sv-0.1`, `MinTypMax` carries `kind`, `span`, positive `width`, optional
`signed`, `choice` (`min`, `typ` or `max`) and selected expression `value`.
The selected expression's width must match the wrapper. The loader validates
the choice and width, then erases the wrapper into the parsed selected operand;
context resizing and two-state conversion remain explicit surrounding nodes.
Unselected arms are not executable envelope operands.

The extractor's `--min-typ-max` option sets the global frontend elaboration
choice. Typical is the default. A nondefault envelope appends top-level
`min_typ_max` with `min` or `max`; absent means `typ`. Regeneration must replay
this field. Symbolic constant folding is unchanged; nonconstant symbolic
choices remain loud and the CLI rejects nondefault symbolic modes. See
[the contract](sv-min-typ-max.md) for selected-only admission and boundaries.

## Static module hierarchy

The legacy `sv-0.1` frontend flattens admitted concrete portless module
instances into the enclosing module's ordinary declarations/processes. The
module carries `hierarchy_lowered: true`; emitted declarations and processes
carry `instance_scope`, a string array describing their structural route.
Generated storage starts with `$hierarchy:` and a length-prefixed scope key.
References use bound declaration identity; no runtime hierarchy lookup or port
copy is implied. Existing expression/statement JSON remains authoritative.

Child ports, interface/program instances, differing timescales, expansion
limits, invalid source and unsupported active members retain explicit walls.
The loader still requires one top module. Symbolic extraction is unchanged.
See [the contract](sv-module-hierarchy.md) for initialization and scope rules
and [the port boundary](sv-hierarchy-ports.md) for the connected-child
repricing decision. Program and interface instances retain an explicit
`Hierarchy:module-kind` unsupported member; see [the kind boundary](sv-hierarchy-kinds.md).

User function, task and DPI declarations remain explicit
`SubroutineSymbol:Subroutine` unsupported members; see [the subroutine
boundary](sv-subroutines.md). No callable frame or external ABI is encoded by
the legacy module envelope.

Gate, switch and pull primitive instances remain explicit
`PrimitiveInstanceSymbol:PrimitiveInstance` unsupported members; see [the
primitive boundary](sv-primitives.md). The envelope has no continuous-driver
or net-resolution node.

`trireg` declarations remain explicit `NetSymbol:TriReg` unsupported members;
see [the charge-storage boundary](sv-trireg.md). The envelope has no
per-net charge state, driver-release transition, charge-strength propagation
or decay publication.

`tri0` declarations remain explicit `NetSymbol:Tri0` unsupported members; see
[the implicit pull boundary](sv-tri0.md). The envelope has no implicit pull
driver, strength ordering or resolved four-state driver set.

`tri1` declarations remain explicit `NetSymbol:Tri1` unsupported members; see
[the pull-up boundary](sv-tri1.md). The envelope has no implicit pull driver,
strength ordering or resolved four-state driver set.

`tri` declarations remain explicit `NetSymbol:Tri` unsupported members; see
[the resolved-wire boundary](sv-tri.md). The envelope has no general driver
set, floating high-impedance state or strength resolution for this spelling.

`interconnect` declarations remain explicit `NetSymbol:Interconnect`
unsupported members; see [the hierarchical-connectivity boundary](sv-interconnect.md).
The envelope has no elaborated port graph, bidirectional connection identity,
per-bit net-type resolution or interconnect delay publication.

Concurrent properties remain explicit `ConcurrentAssertionStatement`
unsupported members; see [the assertion boundary](sv-concurrent-assertions.md).
The immediate-assertion `If` lowering does not encode sampled history,
sequence attempts or assertion-region actions.

Named concurrent-property declarations remain explicit
`PropertySymbol:Property` unsupported members; see [the property boundary](sv-properties.md).
The `sv-0.1` envelope carries no property formals, local-variable frame,
sampled-value history or sequence-attempt state, so declarations are not
inlined into their assertion statements.

Covergroup declarations remain explicit `CovergroupType:CovergroupType`
unsupported members; see [the covergroup boundary](sv-covergroups.md). The
envelope has no sampling event, coverpoint/bin or cross state, so a covergroup
is not flattened into module storage or executed as a procedural block.

Compilation-unit covergroups retain the separate `CovergroupType` unsupported
member. The same sampling and coverage-state boundary applies at that scope;
the envelope does not move the declaration into an artificial module.

Parameterized class declarations remain explicit `GenericClassDefSymbol`
unsupported members; see [the generic-class boundary](sv-generic-classes.md).
The envelope has no value/type parameter environment or specialization table,
so a generic class is not reduced to one default class.

Generic class member/scope recovery retains the separate
`GenericClassDefSymbol:GenericClassDef` unsupported member. The envelope does
not perform class-scope parameter iteration or type-scope lookup as a
specialization shortcut.

Type parameters remain explicit `TypeParameterSymbol:TypeParameter`
unsupported members; see [the type-parameter boundary](sv-type-parameters.md).
The envelope has no type environment or `type(...)` node, so overrides and
dependent declarations are not reduced to the default type.

Final procedures remain explicit `ProceduralBlockSymbol:Final` unsupported
members; see [the final-procedure boundary](sv-final.md). The envelope has no
end-of-simulation invocation phase or completion queue, so a final body is not
run as an initial or concurrent process.

Frontend recovery spans remain explicit `InvalidStatement` unsupported
members; see [the recovery boundary](sv-invalid-statements.md). The envelope
does not execute a bad or partially recovered statement tree.

Configuration declarations remain explicit `ConfigBlockSymbol` unsupported
members. The `sv-0.1` envelope has no library namespace or elaboration-time
configuration resolver, so `design`, `default`, `cell`, `instance`, `use`,
sub-configuration and configuration-localparam bindings are not lowered into
the single-top-module representation. See [the configuration boundary](sv-configurations.md).

Class declarations remain explicit `ClassType` unsupported members. The
`sv-0.1` envelope does not encode class identity, object allocation,
inheritance, method frames, virtual dispatch, random fields or constraints;
class bodies are therefore not rewritten as module declarations. A class
declared inside a module is retained as the separate
`ClassType:ClassType` unsupported member; it is not flattened into that
module. See [the class boundary](sv-classes.md).

Fork blocks remain explicit `BlockStatement:JoinAll`, `BlockStatement:JoinAny`
and `BlockStatement:JoinNone` unsupported members. The envelope does not carry
child-process identities, retained fork continuations, join barriers or
detached-child lifetimes, so these blocks are not rewritten as sequential
statements. See [the fork/join boundary](sv-fork-join.md).


## Dynamic integral casts

The legacy frontend lowers admitted `$cast` calls to existing local captures,
exact membership comparisons, conditionals and stores. Emitted decision nodes
carry `dynamic_cast_lowered: true`; generated captures carry `automatic_cast`
and use collision-audited `$cast:` names. Internal cast-expression/target plans
never cross the envelope boundary. Source-control placement and short circuiting
reuse the plusargs sequencer. Invalid task form keeps an explicit diagnostic
refusal branch. See [the contract](sv-dynamic-cast.md) for types and contexts.


## Fixed-array reduction methods

Admitted fixed-array reduction calls become existing intrinsic-width `Binary`
expressions (or the single original cell/`with` expression for a one-cell array).
The root carries `array_reduction_lowered` with its method name. The actual
bound iterator symbol is substituted during extraction; no iterator variable,
call plan or new runtime node crosses the envelope boundary. A balanced tree
combines pure terms, retaining the result width at every node. See
[the contract](sv-array-reductions.md) for storage and effect boundaries.

## Let expressions

Frontend-bound §11.12 expansions emit the existing expression and statement
nodes; declarations themselves allocate nothing and require no new runtime
node. Same-spelled colliding procedural variables receive `$local:` names
containing the encoded module name, compilation-local buffer ordinal and source
offset. References retain original symbol identity. Whole-source validity and
original-syntax declaration-order checks run before admission. Nonmodule roots
retain a `Module` envelope with an explicit `Hierarchy:module-kind` unsupported
member, so ingestion reports the missing scheduling contract. Symbolic mode
remains unchanged. See [the contract](sv-let-expressions.md).

## Procedural variable lifetimes

Concrete static procedural scalars/packed values/fixed cells emit ordinary
pre-process `Var` declarations with `static_local_storage: true`. Their source
declaration statements emit `Empty`. Original bound symbol identities determine
both lexical and hierarchical storage names. The shared procedural declaration
census replaces the former static-array statement-marker hoist. Actual automatic
scalar `LocalDecl` nodes carry `automatic_scalar: true`, allowing sequential loop
entry while preserving ordinary saved continuations. These flags are frontend
metadata, not new runtime nodes. Closed/pure initialization, cross-initializer
order, default-lifetime provenance and whole-source validity are checked before
admission. Symbolic extraction is unchanged. See
[the contract](sv-procedural-lifetimes.md).

Residual nonclosed static initializers remain explicit `StaticLocal:initializer`
unsupported members; see [the residual boundary](sv-static-initializers.md).
The envelope does not evaluate random/system functions, package-dependent reads,
macro-expanded effects, runtime storage or unrepresented conversion contexts
before process entry, and does not choose an initializer order.

executed as though it were the source design. See the
[repricing boundary](sv-elaboration-invalid.md).
