# Standardized AST envelope — schema sv-0.1 (SystemVerilog payload)

One JSON document per source file, written by
`python3.12 extractors/sv/extract.py <file.sv> [more.sv ...]` (run from the
repo root) as `<file>.sv.json` next to each source. This document is the
normative contract for the Lean ingester (`LeanModels/Sv/**`): every node kind,
field name, and invariant the ingester may rely on is listed here.

The envelope is language-neutral and mirrors `docs/envelope-schema.md` (the
Python payload); the node vocabulary inside `design` is the SV M0 tier of
`docs/sv-design-m0.md`. Widths are **elaborated** widths from pyslang's
compilation (parse + elaboration), not raw syntax — e.g. the unbased unsized
literal `'0` in an 8-bit context is emitted as an 8-bit `Literal`.

Guarantees:

* The extractor **never fails on valid SystemVerilog**. Anything outside the
  vocabulary below becomes `{"kind": "Unsupported", ...}` at the closest
  enclosing node that can no longer be represented; surrounding structure is
  preserved (e.g. a supported assignment whose RHS contains a function call
  keeps its `BlockingAssign` shape with an `Unsupported` value).
* **Deterministic**: same input bytes (and same pyslang version) ⇒ same output
  bytes. `json.dump(..., indent=2)` + one trailing newline, ASCII-escaped
  strings, and fixed key order: `kind` first, then `span`, then the node's
  remaining fields in exactly the order of the tables below. A parsed envelope
  re-serialized with `json.dumps(obj, indent=2) + "\n"` reproduces the file
  byte-for-byte.

## Envelope

```json
{
  "schema_version": "sv-0.1",
  "language": "systemverilog",
  "frontend": {"name": "pyslang", "family": "pyslang-11"},
  "source_file": "Examples/system-verilog/adder/adder.sv",
  "source_sha256": "<hex sha256 of the source bytes>",
  "design": {"kind": "Design", "modules": [<module>...], "others": [<Unsupported>...]},
  "lean_blocks": []
}
```

**`frontend` is stamped by FAMILY, never by point release** (`pyslang-11`,
not `11.0.0`). The family is what the envelope depends on — pyslang 11.x
parses and elaborates the same way, and the patch digit is not a semantic
input. Stamping the point release put a version string in the bytes of
every envelope, which was harmless while the round-trip gate was
simulator-gated and SKIPped, and became a live hazard the moment that gate
became an unconditional CI step against an unpinned `pip install pyslang`:
the next patch release would have reported all 21 envelopes as `DIVERGE`
on every PR, for a reason unrelated to any change. Same spelling as
`extractors/sv/census.py`, so the two instruments agree.

**Three envelopes still carry the old `"version": "11.0.0"` key**, and
deliberately so: `alu_div`, `ff_one` and `popcnt` under
`Examples/system-verilog/` record `source_files` as absolute paths into a
scratch directory on a machine that no longer exists, so they cannot be
regenerated by anyone. `harness/sv_round_trip.py` reports them as
`REFUSE sources-not-in-tree` with **live=false** and never compares their
bytes. They were left untouched rather than hand-edited, because editing
them would make them look regenerated when they cannot be.

Top-level key order: `schema_version`, `language`, `frontend`, `source_file`,
`source_sha256`, `design`, `lean_blocks`. `source_file` is the (normalized,
`/`-separated) path exactly as passed on the command line. `lean_blocks` is
reserved and always `[]` in M0 (companion blocks are not scanned).

`design.modules` holds one `Module` per **top-level** module instance, in
elaboration (source) order. M0 is single-module; module instantiations inside a
module appear as `Unsupported` members, and `$unit`-scope compilation-unit
members (imports, unit variables, ...) appear as `Unsupported` nodes in
`design.others` (normally `[]`).

## Spans

Every node carries `"span"`: `{"line": L, "col": C, "end_line": EL,
"end_col": EC}` — slang's numbers: **1-based** lines and columns, end
**exclusive**. `span` may be `null` when no source range is available (only on
synthesized/degenerate nodes; never on the M0 examples).

## `Unsupported`

```json
{"kind": "Unsupported", "span": {...}, "sv_kind": "<tag>", "text": "<source text, <= 200 chars>"}
```

May appear anywhere a module member, port, decl, process, statement, or
expression is expected. `text` is the exact source slice of the offending
construct (whitespace-stripped, truncated to 200 chars, possibly `""`).
`sv_kind` is the slang AST class name, optionally qualified with `:detail`
(mirroring the Python lane's `"BinOp:Div"` convention). Tags the extractor
emits:

| tag | meaning |
|---|---|
| `<SlangClass>` | node class outside the vocabulary, e.g. `ForLoopStatement`, `CallExpression`, `ElementSelectExpression`, `RangeSelectExpression`, `ReplicationExpression`, `StringLiteral`, `RealLiteral`, `EmptyStatement`, `VariableDeclStatement`, `CaseStatement`, `InvalidStatement`, `InvalidExpression` |
| `InstanceSymbol:Instance`, `SubroutineSymbol:Subroutine`, `ParameterSymbol:Parameter`, ... | module member kinds outside M0 (class name `:` symbol kind) — routed to the module's `others` list |
| `ProceduralBlockSymbol:Initial` / `:Final` / `:AlwaysLatch` | process kinds outside M0 |
| `ProceduralBlockSymbol:NoEventControl` | `always` / `always_ff` whose body is not an event-controlled statement |
| `TimedStatement:<TimingClass>` | timing-control classification — supported integral-literal `#d` forms become `Delay`, and simple nested `@(posedge sig)` / `@(negedge sig)` / `@(sig)` forms become `WaitEvent`; unsupported delay expressions, event lists, and `TimedStatement:ImplicitEventControl` for `@*` remain loud |
| `SignalEventControl:BothEdges` | edge other than `posedge`, `negedge`, or a bare signal expression |
| `SignalEventControl:iff` | `@(posedge clk iff ...)` |
| `SignalEventControl:clock` | edge expression that is not a 1-bit identifier |
| `AssignmentExpression:compound` | compound assignment whose scalar binary operator is outside the admitted set or whose target is not a plain identifier |
| `AssignmentExpression:compound-width` | compound assignment whose elaborated operands do not share the destination width |
| `AssignmentExpression:timing` | intra-assignment timing (`a <= #3 b`) |
| `AssignmentExpression:target` | assignment LHS that is not a plain identifier (bit/part-select, concat LHS, ...) |
| `ExpressionStatement:<Class>` | expression statement that is not an assignment (`i++;`, void call, ...) |
| `ContinuousAssignSymbol:delay` / `:form` | `assign #5 ...` / malformed continuous assign |
| `ConditionalStatement:Unique` / `:Unique0` / `:Priority` / `:multi` / `:pattern` | `unique`/`priority` if, multiple `&&&` conditions, `matches` pattern |
| `ConditionalExpression:multi` / `:pattern` | same, for `?:` |
| `BlockStatement:JoinAll` / `:JoinAny` / `:JoinNone` | `fork ... join*` |
| `BinaryExpression:<Op>` / `UnaryExpression:<Op>` | operator outside the M0 set, slang enum name (e.g. `BinaryExpression:Divide`) |
| `ConversionExpression:width` | **width mismatch in source**: an implicit conversion that changes bit width (M0 has no implicit extension/truncation rules) |
| `ConversionExpression:Explicit` / `:BitstreamCast` / `:StreamingConcat` | explicit casts |
| `NamedValueExpression:<SymbolKind>` | identifier that does not name a variable/net (e.g. `:Parameter`) |
| `PortSymbol:InOut` / `:Ref` | port directions outside in/out |
| `PortSymbol:...`, `VariableSymbol:...`, `NetSymbol:...` with `:2state` / `:range` / `:type` | unsupported declared type: 2-state nets or symbolic declarations, multidimensional packed ranges, unpacked/nonintegral types (real, string, ...); the legacy/self-check path admits one-dimensional packed scalar ranges and untagged packed struct/union vectors |
| `NetSymbol:<NetKind>` / `:delay` | net kinds other than `wire` (`Tri0`, `WAnd`, ...), net delays |
| `ExtractorInternal:<PyException>` | defensive catch-all: the extractor itself failed on this node (should not occur; `span` is `null`, `text` is the Python error) |

The tag list may grow with the tier; ingesters must treat **any** unknown
`sv_kind` as simply "unsupported" (the interpreter returns `.unsupported` when
an `Unsupported` node is reached).

## Module

Key order: `kind`, `span`, `name`, `ports`, `decls`, `processes`, `others`.

```json
{"kind": "Module", "span": {...}, "name": "adder",
 "ports": [<port>...], "decls": [<decl>...], "processes": [<process>...], "others": [...]}
```

Members are routed by category, each list in source order: `ports` (port list
entries), `decls` (module-level variables and nets, **excluding** the internal
symbols that back ANSI ports — a port appears only in `ports`), `processes`
(procedural blocks and continuous assigns), `others` (everything else —
functions, parameters, instances, generate blocks, ... — as `Unsupported`;
`[]` on M0-clean sources). Statement-level `begin/end` scope symbols are
elaboration artifacts and are silently skipped (their statements appear inside
the owning process body).

### Port

Key order: `kind`, `span`, `name`, `dir`, `width`, optional `signed`, optional `two_state`, optional `init`.

```json
{"kind": "Port", "span": {...}, "name": "a", "dir": "in", "width": 8,
 "signed": true}
```

`dir` ∈ `"in" | "out"`. `width` is the elaborated bit width (scalar `logic` ⇒
`1`). Legacy integral variable ports admit scalar, `[W-1:0]` packed and
predefined integer types (`byte`, `shortint`, `int`, `longint`, `integer`,
`time`). A four-state type omits `two_state`; a two-state **input or output
variable** carries `"two_state": true`. Startup and every input stimulus
convert x/z bits to zero before expression evaluation. The time-zero runner
models an unconnected four-state input as z and a two-state input as zero;
the cycle runner models a connected, initially unknown external driver.
Signed types carry optional `signed: true` metadata independently of their
state count. Two-state nets, reversed-range, aggregate, symbolic two-state
and symbolic signed declarations remain `Unsupported`.

`init`, when present, retains the input's default expression or the output
variable's initializer, including two-state conversion. The time-zero runner
evaluates it before processes execute. The connected cycle runner ignores
input defaults and evaluates closed output initializers; state-dependent
initializers are loud there. Invalid output-net port initializers remain
loud, rather than being mistaken for variable startup. A separate internal
initializer on an input variable also remains loud until its initialization
and incoming-driver interaction is modeled.

### Declarations

Key order: `kind`, `span`, `name`, `width`, optional `signed`, `init`.

```json
{"kind": "Var", "span": {...}, "name": "a", "width": 8, "signed": true, "init": <expr> | null}
{"kind": "Net", "span": {...}, "name": "w", "width": 8, "signed": true, "init": <expr> | null}
```

`Var` = `logic`/`reg` variable; `Net` = `wire`. Same type restrictions as
ports (4-state, scalar or `[W-1:0]`; other net kinds, delays,
2-state/reversed-range/multi-dim types ⇒ `Unsupported`; signedness is retained
as metadata). `init` is the
declaration initializer, already width-resolved. LRM note: a **Var** initializer
is a time-0 assignment (the M0 examples use exactly this); a **Net** initializer
is per LRM an implicit *continuous assign* driver — no M0 example uses one, and
the ingester may treat a `Net` with non-null `init` as it treats `Assign`.

## Processes (`processes` list entries)

| kind | key order / fields |
|---|---|
| `AlwaysPosedge` | `kind`, `span`, `style` (`"always_ff"` \| `"always"`), `clock` (string: the 1-bit clock identifier), `body` (stmt) |
| `AlwaysComb` | `kind`, `span`, `body` (stmt) |
| `Assign` | `kind`, `span`, `target` (expr: `Ident`, a select, or semantic-tier `ConcatTarget`), `value` (expr) — continuous `assign` |
| `Initial` | `kind`, `span`, `body` (stmt) — scheduler-facing retained process; the timed loader admits one or more in source order |

`AlwaysPosedge` covers exactly `always_ff @(posedge clk) ...` and
`always @(posedge clk) ...`; `style` records which keyword the source used —
**M0 cycle semantics treats both identically** (edge-phase processes). Any
other sensitivity (negedge, event lists, `@*`, `iff`, delays, always_latch,
initial, final) makes the whole process `Unsupported` in this list. A scheduler
envelope may instead carry `Initial` processes for the timed loader described
below. `body` is a single statement node (often `Block` or `If`).

The scheduler-facing timed loader admits one or more `Initial` processes and
`AlwaysPosedge` processes. Initial bodies run from Active at time zero in source
order; each clocked process is lowered to a retained `WaitEvent` followed by
its body and re-armed after completion. The legacy self-check runner remains
initial/time-zero-only and refuses non-initial processes and timed nodes.

## Statements

The legacy/self-check extractor also lowers unqualified ordinary integral
`case` statements into nested `If` nodes with `Binary` `===` conditions.
Each lowered `If` carries optional `case_lowered: true` provenance; the
existing statement ingesters need no additional constructor. Subject and
label expressions retain slang's whole-case context conversions and must
belong entirely to the admitted pure integral fragment. Purity is checked
over the bound source tree before constant conversion, so a binder-folded
call or increment cannot disappear into an admitted literal. Source-order
first-match search ends in the source default (if any), independent of
its original placement. Unsupported qualifiers, wildcard/pattern forms,
effectful/nonintegral expressions and default-only cases retain
`CaseStatement:<reason>` refusals. A frontend error in such a compilation
adds top-level `CaseStatement:invalid-compilation`. This lowering does not
change symbolic `sv-0.2` `Case` nodes.

An admitted fixed-size `$bits` query is a pure unevaluated leaf in this
source-tree check. Its argument subtree is skipped, not admitted as an
ordinary effectful expression.

| kind | key order / fields |
|---|---|
| `Block` | `kind`, `span`, `stmts`: [stmt...] — `begin ... end` (a single-statement body still nests one level: `"stmts": [<stmt>]`) |
| `BlockingAssign` | `kind`, `span`, `target` (`Ident`; legacy/self-check also `SelectTarget` or `ConcatTarget`), `value` (expr) — `=` |
| `NonblockingAssign` | `kind`, `span`, `target` (`Ident`; legacy/self-check also `SelectTarget` or `ConcatTarget`), `value` (expr) — `<=` |
| `If` | `kind`, `span`, `cond` (expr), `then` (stmt), `else` (stmt \| `null`) — `else if` chains nest as `If` inside `else` |
| `For` | legacy/self-check: `kind`, `span`, `initializers` (statement array), `condition` (expr), `steps` (statement array), `body` (stmt) |
| `Repeat` | legacy/self-check: `kind`, `span`, `count` (expr), `count_signed` (Bool), `body` (stmt) |
| `Delay` | scheduler: `kind`, `span`, `amount` (Nat below 2^64), `body` (stmt) — a known nonnegative integral-literal delay; ingestion retains the body after the delay checkpoint, and runtime refuses `amount == 0` because Inactive delivery is not in this tier |
| `WaitEvent` | scheduler: `kind`, `span`, `signal` (1-bit identifier), `edge` (`"posedge"`, `"negedge"`, or `"any"`) — a simple nested event wait; an enclosing `Block` retains the following body and the self-check runner refuses it |
| `Break` / `Continue` | legacy/self-check: `kind`, `span`; transfer to the nearest loop |
| `Unsupported` | see above |

The plain M0 cycle runner still accepts whole-signal identifier targets only;
a bit-select, part-select or concatenation LHS makes that *statement*
`Unsupported` (`AssignmentExpression:target`). In the legacy/self-check
extractor, a constant element of a one-dimensional fixed-unpacked integral
array is lowered
to an identifier cell such as `mem[2]`, and its declaration is expanded to one
vector `Var` per cell. Dynamic or out-of-range indices, multidimensional or
aggregate arrays, and whole-array operations remain loud except for the narrow
bounded dynamic access and whole-array positional-pattern assignments below.
`If` conditions may be any width (truthiness per LRM: true iff some bit is `1`).

An eligible cell-expanded declaration may also have an exact-length
assignment-pattern initializer; each element is converted once and stored in
its corresponding cell. Positional and elaborated keyed/default patterns are
admitted, as are replicated patterns whose constant count times their inner
element count equals the array length. Wrong-length, effectful or aggregate
initializers remain `Unsupported`.

The same representation admits an exact-length assignment-pattern statement to
an eligible cell-expanded array. Positional patterns and elaborated
keyed/default structured patterns lower to a `Block` of per-cell
`BlockingAssign` or `NonblockingAssign` nodes, in declared index order. A
replicated pattern is admitted when its constant repetition count times its
inner element count equals the array length. Each element must be a pure
integral expression and must not read the destination array, preserving the
source rule that the complete RHS is evaluated before any cell is updated.
Wrong-length, dynamic, aggregate and destination-aliasing patterns remain
`Unsupported`.

A simple right-streaming unpack (`{>> {a, b, ...}} = source`) with no slice
size and only direct integral identifier targets reuses `ConcatTarget`. The
RHS must be at least as wide as the target leaves; excess source MSBs are
consumed by the existing packed-target resize. Left streaming, nested or
effectful stream operands, struct/unpacked aggregates and a narrower source
remain `Unsupported`.

An equal-length whole-array assignment from another eligible fixed-unpacked
integral array is lowered to the same per-cell block, pairing source and
destination cells in declaration order. Different lengths, incompatible
element widths, conditional aggregate expressions and unsupported storage
forms remain `Unsupported`.

An equal-length simple constant slice copy uses the same pairing for the
selected cells, including a whole-array source or destination on either side.
Overlapping self-copies remain `Unsupported` because the cell-expanded state
does not provide a temporary aggregate snapshot; dynamic, indexed and
out-of-range slices remain loud.

Equality and inequality of equal-length whole arrays or simple constant slices
are lowered to pairwise cell comparisons joined with logical `&&`. Unequal
shapes, aliasing forms and unsupported aggregate types remain `Unsupported`.
Case equality and inequality (`===`/`!==`) use the same lowering, preserving
exact x/z comparison through the existing scalar case operators.

An exact-length unpacked-array concatenation on the RHS of an eligible fixed
array assignment is flattened in operand order and lowered to the same per-cell
assignments. Scalar operands and existing whole-array/simple-slice operands are
accepted when their widths match; a source alias of the destination, dynamic
or aggregate operands, and mismatched lengths remain `Unsupported`. A typed
simple assignment-pattern operand is accepted when its one-dimensional fixed
array elements are pure integral values of the destination width; replication,
nested aggregates and mismatched pattern widths remain `Unsupported`.

A positional unpacked assignment-pattern LHS such as `U3'{a, b, c} = source`
is likewise lowered when its RHS is an eligible fixed-unpacked integral array
or simple constant slice and every pattern element is a distinct direct scalar
target. Each source cell is converted to its destination width and state kind
before the existing blocking or nonblocking assignment is emitted. Nested or
effectful pattern elements, duplicate targets, source/destination aliases and
aggregate or dynamic forms remain `Unsupported`.

An assignment whose RHS is a pure one-condition ternary over two eligible
fixed arrays is lowered cell by cell to `Ternary` values. The condition is
shared across the cells, so an x condition retains the ordinary per-bit
conditional merge. Conditional aggregate forms with patterns, calls, unequal
shapes or unsupported storage remain `Unsupported`.

The same lowering admits equal-length simple constant slices on the
destination and both branches. Overlapping source/destination array names are
rejected because the cell-expanded state has no aggregate snapshot; dynamic,
indexed and out-of-range slice forms remain `Unsupported`.

An exact-length positional pattern on a simple in-range constant slice of an
eligible fixed array is lowered to the selected cells in source order.
Elaborated keyed/default patterns and constant replicated patterns whose count
equals the slice length use the same lowering. Dynamic, indexed, out-of-range
and mismatched slice forms remain `Unsupported`.

For a one-dimensional fixed-unpacked integral array whose declaration has been
expanded to cells, a pure integral dynamic index is lowered to a finite
conditional over the declared cells. Dynamic writes become mutually exclusive
`If` branches; dynamic reads become a `Ternary` chain. Case-equality against
the declared index labels makes x/z indices and out-of-range indices perform
no write and read as all x. Associative, dynamic, queue, multidimensional and
effectful index forms remain `Unsupported`.

The symbolic `sv-0.2` tier also admits a continuous assignment whose LHS is a
nested concatenation of direct scalar, constant bit-select, or constant
part-select leaves. The extractor flattens nested concatenations into a
`ConcatTarget` in source order. `Design2` samples the RHS once and applies its
MSB-to-LSB slices to the existing packed-vector windows during comb settling;
aggregate storage and a second scheduler are not introduced. Empty, dynamic,
aggregate, duplicate, aliased, or effectful forms remain `Unsupported`.

The same symbolic process representation carries a single constant `BitSel`
or `PartSel` target. Multiple such assignments settle in process order into
their existing vector windows, so disjoint partial drivers retain undriven
bits and update live when an input changes. Dynamic or effectful selections,
overlapping driver resolution, and legacy/self-check selected assignments
remain outside this surface.

The `bit_select_assign` fixture exercises two disjoint constant bit-select
drivers, including a selected read on the RHS and four-state propagation. It
uses the same `BitSel` window path; no separate scalar-driver representation
or scheduler is introduced.

An untagged packed-struct variable may use a direct integral member as a
constant window in the symbolic tier. An untagged packed union uses the same
single-vector representation, so an alternate field aliases the written
bits. The extractor lowers each direct member's fixed declaration offset to a
`PartSel` over the synthetic packed vector, so writes and reads use existing
storage. Tagged structs/unions, nested unions, unpacked members and dynamic
member paths remain loud. A typedef naming an untagged packed struct is
compile-time metadata and is skipped after its canonical vector width has been
checked; `packed_member_typedef` pins that case.

Nested untagged packed-struct member chains are flattened in the same way:
the helper accumulates each declaration offset and emits one outer-vector
`PartSel`. `packed_member_nested` pins this chain; nested unions and other
aggregate member paths remain unsupported.

Literal indexed part-selects (`base +: width` and `base -: width`) are
normalized to ordinary constant `PartSel` bounds when the selected window is
in range. Dynamic or parameter-dependent bases and out-of-range windows remain
`Unsupported`; `indexed_part_assign` pins the accepted source-order form.

## Expressions

The legacy/self-check blocking path additionally emits `SelectTarget` for
a packed bit or part destination. Its fields are `kind`, `span`, `width`,
`value` (an `Ident` base), `index` (an expression), `index_signed`,
`descending` and `two_state` (booleans). Simple parts use their low bound;
indexed-down parts use their high base and set `descending`. The bound
index retains its original width and signedness, and each destination
retains its own two-state conversion. This node is an assignment target,
not a readable expression.

For a one-dimensional packed scalar source with a noncanonical declared range,
the legacy extractor admits in-range constant bit selects and simple
constant part selects. It records the normalized LVec offset of the right
bound as a `Literal` index and forces unsigned offset interpretation; dynamic,
out-of-range and indexed part-selects remain `Unsupported` until their
declared bounds are represented directly.

Direct fields of an untagged packed struct or packed union are represented by
the same window nodes: the field's fixed `bitOffset` becomes a literal LVec
index over the aggregate identifier. A chain through nested packed structs is
flattened to the outer aggregate's fixed bit offset. Nested unions, unpacked
struct/union fields, classes, interfaces and tagged unions remain unsupported.

`ConcatTarget` has `kind`, `span`, `width` and `parts` (source-ordered
targets), with nested `ConcatTarget` nodes retained. Whole `Ident` leaves
add a `two_state` boolean; selected leaves retain the fields above.
Ingestion flattens nested concatenations to width-bearing `PackedTarget`
leaves and checks every recorded aggregate width. RHS slices are assigned
from the low end of the rightmost leaf. `AssignmentOrder` is an evaluator
parameter, not an extractor field or a compiler-selected order; the named
default is right-to-left. The RHS is captured once, and each index is
evaluated against the then-current frame at its chosen destination step.
An order must be a permutation of all leaf indices, or execution refuses.

Selected nonblocking targets use the same `SelectTarget` shape in the
legacy/self-check surface. The RHS and index are sampled against the active
state; the queue records a full-value snapshot derived from the last pending
snapshot for that signal, preserving disjoint merges and issue order at
commit. Concatenated nonblocking targets use `ConcatTarget` and flatten to
the same ordered `PackedTarget` leaves as blocking concatenations. Nested
targets retain their envelope shape, while the self-check parser flattens
them for queue insertion. Invalid compilations containing an admitted target
retain `SelectTarget:invalid-compilation` or
`ConcatTarget:invalid-compilation`. Partly out-of-range writes follow the
per-bit rule in the value primitive, with simulator disagreements kept as
diagnostics rather than hidden by a second semantic path.

The legacy/self-check vocabulary also includes `BitQuery` for IEEE
1800-2023 §20.9. Its fields are `kind`, `span`, `width`, `op`, `operand`
and `controls` (an expression array). `op` is `$countbits`, `$countones`,
`$onehot`, `$onehot0` or `$isunknown`; only `$countbits` has controls,
with at least one. Controls retain their original widths: evaluation
uses each least-significant bit and ignores repeated control values when
counting positions. The operand is not widened to the result's width.
The two count functions have `width: 32` and `signed: true`; predicates
have `width: 1` and unsigned results. The current admission is integral
and effect-free; the symbolic `sv-0.2` vocabulary is unchanged.

Every supported expression node carries `width`: its **elaborated result width
in bits**. (`Unsupported` expression nodes have no `width`.)

| kind | key order / fields | width invariant |
|---|---|---|
| `Ident` | `kind`, `span`, `width`, `name` (string) | declared width of the named var/net/port |
| `Literal` | `kind`, `span`, `width`, `bits` (string), optional `signed`, `fixed_bits_query`, `fixed_clog2`, `fixed_dimension_query` provenance | `len(bits) == width` |
| `Unary` | `kind`, `span`, `width`, `op` (`"~"` \| `"!"` \| `"+"` \| `"-"`), `operand` (expr) | `~`,`+`,`-`: `width == operand.width`; `!`: `width == 1` |
| `Reduce` | `kind`, `span`, `width`, `op` (`"|"` \| `"&"` \| `"^"` \| `"~|"` \| `"~&"` \| `"~^"`), `operand` (expr) | `width == 1`; operand is any admitted integral expression |
| `Binary` | `kind`, `span`, `width`, `op` (see below), `left`, `right` (exprs) | arithmetic/bitwise operators: common-width children; shifts: `width == left.width`, with a self-determined right operand; comparisons: `width == 1` and equal child widths |
| `Ternary` | `kind`, `span`, `width`, `cond`, `then`, `else` (exprs) | `width == then.width == else.width`; `cond` any width |
| `Concat` | `kind`, `span`, `width`, `parts`: [expr...] | `width == sum(part.width)` |
| `Unsupported` | see above | — |

`Binary` `op` ∈ `"+" "-" "*" "u/" "s/" "u%" "s%" "&" "|" "^" "==" "!=" "===" "!==" "==?" "!=?" "&&" "||" "<" "<=" ">" ">="` (the M0 set;
`<<` `>>` `<<<` and `>>>` are integral shifts (§11.4.10). Their envelope
operators are typed as `u<<`/`s<<`, `u>>`/`s>>`, `u<<<`/`s<<<`, and
`u>>>`/`s>>>`; the prefix records the signedness of the left operand.
The right operand is always unsigned and self-determined. The result width
is the left operand width, including assignment-context widening before the
shift and destination narrowing after it. Unknown shift amounts produce all
x; overshifts zero-fill, except signed `>>>`, which sign-fills.

`==`/`!=` are *logical* equality. `===`/`!==` are *case* equality: they
compare every four-state bit exactly and always produce a definite one-bit
result. The width invariants hold
whenever the children are supported nodes — the extractor enforces them and
demotes violators to `Unsupported`; if a child is itself `Unsupported` its
width is unknown and the parent keeps its structure (the interpreter goes
`.unsupported` on reaching the child).

Logical `&&`/`||` also produce a one-bit result. Each operand is converted by
the four-state truthiness rule before the logical table is applied; they are
not bitwise aliases for `&`/`|`.

Wildcard `==?`/`!=?` produce an unsigned, one-bit self-determined result.
Right x/z positions match every left value; all other positions use logical
equality. A definite mismatch dominates an unknown cared-left position.
Both operand widths agree after the elaborated conversions. Surrounding
assignment or arithmetic context widens the result after the comparison,
while its operands retain their own width and signedness. The same spellings
are retained in symbolic `sv-0.2` expressions.

Unary reductions `|`, `&`, `^`, `~|`, `~&` and `~^` produce one-bit values.
The first three fold the operand's bits with the corresponding four-state
table; the last three negate those results. Unknown bits remain `x` unless a
definite table result decides the fold (`|4'b100x` is `1`, while `&4'b111x`
and `^4'b101x` are `x`).

Unary `+` remains a `Unary` node through extraction and symbolic sizing.
IEEE 1800-2023 §11.4.3 requires the arithmetic x/z rule: a fully known
operand is unchanged, while any x/z bit makes the entire result x. The
shared `LVec.pos` rule applies after context sizing, including when the
unary expression occurs inside another arithmetic operand.

Runtime integral division uses `u/` for unsigned operands and `s/` when
both elaborated operands are signed. Zero divisors and x/z operands give
all x; known signed quotients truncate toward zero at the common width.
Plain scalar `/=` lowers to the same operator. Symbolic constant positions
retain `/` for integer elaboration, while runtime vector division retains
typed operators and unfolded `Resize`/`SignedResize` operands. Instantiation
recomputes their context widths, including signed constants, without
widening self-determined Boolean operands or ternary conditions. Real
division and selected compound targets stay loud. See `docs/sv-division.md`.

Runtime integral remainder uses `u%` for unsigned operands and `s%` when
both elaborated operands are signed. Zero divisors and x/z operands give all
x; signed remainders follow truncation-toward-zero division and therefore
the dividend's sign. Plain scalar `%=` uses the same typed operator. Constant
symbolic positions retain `%` for integer elaboration; runtime vector
remainder retains the typed operators and the same context-width conversion
rules as division. Real remainder and selected compound targets stay loud.
See `docs/sv-remainder.md`.

Integral `*` uses the same elaborated common-width invariant as `+` and
`-`. Operand `Resize`/`SignedResize` nodes act before multiplication;
destination narrowing acts after it. A four-state unknown in either
operand makes the entire product unknown. Plain scalar `*=` lowers to a
`Binary *` reading the original target, while selected compound targets
stay loud. `Multiplication:invalid-compilation` prevents a frontend error
elsewhere in a product-containing module from being silently discarded.
In sv-0.2, constant multiplication still elaborates to an integer literal;
nonconstant multiplication instantiates the runtime `.mul` operator.

The extractor transparently unwraps slang's **same-width implicit/propagated
conversions** (elaboration artifacts: 2-state literal into a 4-state context,
sign reinterpretation) — they never appear in the envelope. *Width-changing*
implicit conversions are the M0 "width mismatch in source" case ⇒
`ConversionExpression:width`.

### `Literal` — 4-state constants

The legacy/self-check extractor also folds a pure constant `$clog2` call
(IEEE 1800-2023 §20.8.1) to a signed 32-bit `Literal`. Such a literal carries
`fixed_clog2: true` provenance. The bound argument must be one integral,
effect-free expression that slang has evaluated during elaboration; zero and
one produce zero, and the argument is treated as unsigned, so a 32-bit `-1`
produces 32. Dynamic, effectful, malformed and nonintegral calls remain
`Unsupported`, and a frontend error in a compilation containing an admitted
call adds `$clog2:invalid-compilation`. No new runtime or scheduler rule is
introduced.

It also folds `$size`, `$high`, `$left`, `$right`, `$low`, `$increment`,
`$dimensions` and `$unpacked_dimensions` for fixed integral types and fixed
arrays thereof (array-query system functions, §20.7). The result is a signed
32-bit `Literal` carrying `fixed_dimension_query` with the query name;
dimensions are numbered from one, unpacked before packed, retaining each
declared left/right bound. A predefined integer, enum or packed aggregate
contributes its implicit packed bit dimension; a plain scalar contributes none.
Tagged unions are outside this dimension-query slice. `$size` is
`abs(left - right) + 1`, `$high`/`$low` select the larger/smaller bound,
and `$increment` is one for descending or equal bounds and minus one for
ascending bounds. The count queries return total and unpacked dimension counts.
The six bound/size/direction queries accept an optional pure, frontend-bound
constant dimension selector, defaulting to one. Literal and parameter/enum
leaves do not need a cached evaluation; other unbound compound selectors stay
loud without invoking an evaluation context. Runtime or invalid selectors,
dynamic/associative/queue arrays, effectful operands, malformed calls and
nonintegral element types remain `Unsupported`, with
`DimensionQuery:invalid-compilation` retained for an admitted query in an
otherwise erroneous compilation.

The legacy/self-check extractor also emits signed 32-bit `Literal` nodes
for `$bits(expression)` or `$bits(data_type)` with fixed-size bitstream
arguments (IEEE 1800-2023 §20.6.2). Their `bits` encode the bound type's
`bitstreamWidth` modulo `2^32`, with `signed: true` and optional provenance
`fixed_bits_query: true`. The argument is not evaluated or converted;
pure metadata expressions and unsupported runtime types can be queried.
Admission deliberately rejects effectful bound operand syntax, including
calls other than nested admitted queries, assignments and increments.
IEEE specifies no evaluation even for those operands, but this tier keeps
them loud after a licensed reference disagreed on a direct increment.
Context resizing retains this query literal rather than folding away its
admission evidence. Dynamically sized and non-bitstream arguments remain
`Unsupported`; a frontend error in a compilation containing an admitted
query adds top-level `$bits:invalid-compilation`. Existing literal
ingesters require no new constructor, and symbolic `sv-0.2` `SysCall`
queries are unchanged.

A zero-argument `$time` expression in the time-zero self-check slice is also
folded to a 64-bit all-zero `Literal` with `time_zero: true` provenance. The
self-check runner has no elapsed time; delays, event waits, `$realtime` and
malformed `$time` calls remain loud. This uses the existing `Literal` node and
does not add a scheduler rule.

```json
{"kind": "Literal", "span": {...}, "width": 8, "bits": "1x0z1010"}
```

`bits` is a string over `{'0','1','x','z'}` (lowercase), length exactly
`width`, written **MSB-first** — the same order as SV source and `$display %b`
output: `8'b1x0z_1010` ⇒ `"1x0z1010"`, `8'd2` ⇒ `"00000010"`, `'0` in an 8-bit
context ⇒ `"00000000"`, `'1` ⇒ `"11111111"`, `'x` ⇒ `"xxxxxxxx"`.

> **Ingester warning — bit order.** `LeanModels.Sv.LVec` is **LSB-first**
> (`bits[0]` is bit 0). `bits` here is MSB-first, so the ingester must
> **reverse the string**: `LVec.bits[i] = bits[width - 1 - i]`. This is the
> one place the envelope and the Lean value core differ in orientation.

x/z digits are preserved exactly as written (after slang's per-digit
expansion, e.g. `8'bx` ⇒ `"xxxxxxxx"` per the LRM's leading-digit extension
rule). Unsized bare integers (`1`, which is a signed 32-bit `int`) only occur
behind width-changing conversions in M0 code and therefore surface as
`Unsupported` unless the context is exactly 32 bits wide.

# Symbolic mode — schema sv-0.2 (additive; `--top`)

Phase 1 of the CV32E40P program adds a second extraction mode:

```
python3.12 extractors/sv/extract.py --top <module> <files...> [-I <incdir>] [-o out.json]
```

All sources are compiled as **one** slang compilation (multi-file is for
**name resolution only**: package imports, typedefs, enum types) and exactly
the named top module is emitted, as one envelope (default output path: next
to the file that defines the top module, `<file>.sv.json`). Everything in
this section is **additive**: single-file mode (`--top` absent) is untouched
and remains byte-identical at schema `sv-0.1`.

Two design laws govern this mode (they are the point of the program):

1. **Parameters stay symbolic.** Parameter *values* are never folded into
   the envelope's primary form. A parameter reference in any expression
   position is a `ParamRef` node; declared widths are the source's symbolic
   range expressions. On the Lean side (phase 2) a parameterized module
   becomes a Design-valued *function* of its parameters, enabling ∀-width
   theorems.
2. **Generate stays structural.** A generate-for is ONE `GenerateFor` node
   (genvar, symbolic header expressions, body template) — an indexed family
   the prover handles by induction; a generate-if is ONE `GenerateIf` with a
   symbolic condition. Nothing is unrolled.

**Symbolic-primary / resolved-secondary convention.** Wherever slang only
exposes post-elaboration integers, the envelope carries the recovered
symbolic form as the primary field and the defaults-elaborated integer in a
`resolved`-family field beside it, for phase-2 cross-checks only:
`resolved` = elaborated *value* (on `ParameterDecl`/`LocalParam`/`SysCall`),
or elaborated *bit width* (on `PackedType`/`TypeRef`); `resolved_width` =
elaborated context width (on `Int`/`Fill`); `resolved_count` = number of
elaborated instances (on `GenerateFor`). Ingesters MUST treat these as
metadata, never as the contract.

**Recovery method and honest limits.** (a) Bound expressions are used
wherever slang retains them — parameter/localparam initializers
(`ParameterSymbol.initializer`), generate-for headers
(`initialExpression`/`stopExpression`/`iterExpression`), generate-if
conditions (`conditionExpression`), and every process/assign expression;
in these trees parameter references are still symbol references, emitted as
`ParamRef`/`GenvarRef`/`EnumRef`. (b) The one place slang folds without
keeping a bound expression is the packed **dimensions of declared types**
(resolved to integer ranges); those are recovered from the declaration's
*syntax tree* and identifiers in them are classified via `lookupName` on the
top module's body scope. Limits: syntax-recovered nodes carry `"width":
null` (they are not re-type-checked); a dimension identifier not visible
from the top module's scope (e.g. a package-private name never imported)
degrades to an `Unsupported` node with the `resolved` width still present
(`"packed": null` when a whole dimension list is unrecoverable); genvar
references are recognized *by name* against the enclosing generate stack;
`width` fields on ordinary expression nodes inside processes are elaborated
under **default** parameter values (cross-check only — the binding symbolic
widths are on the declarations); the body template of a `GenerateFor` is
bound from its first elaborated instance (a loop with zero instances under
defaults keeps its body as one `Unsupported` node with the source text);
untaken generate-if branches ARE emitted (slang binds them in
uninstantiated mode).

Top-level key order: `schema_version` (`"sv-0.2"`), `language`, `frontend`,

references), `design`, `lean_blocks`. `design.modules` holds exactly one

Symbolic-mode changes to existing nodes: `Port`/`Var`/`Net` carry their
declared type object (`PackedType` or `TypeRef`) in the `width` field
(instead of an integer); enum-typed ports/vars/idents are in-vocabulary;
multi-dimensional packed vectors of 4-state unsigned scalars are
in-vocabulary (`packed` lists one `{msb, lsb}` per dimension, outermost
first). In **symbolic expression positions only** (parameter defaults,
localparam exprs, generate headers and conditions, dimension bounds) the
operator set additionally admits `* / % ** << >> <<< >>>`; in ordinary
process/assign positions the M0/self-check operator set is unchanged and
everything else remains `Unsupported` (selects, case, event lists,
instantiations, 2-state types, ... — phase 2+ tiers). A width-changing
implicit conversion whose operand contains symbolic references is emitted
as `Resize` around the symbolic operand (unsigned operands; signed →
`Unsupported`) instead of being constant-folded.

New `Unsupported` tags of this mode: `Syntax:<SyntaxKind>` /
`Syntax:Identifier:unresolved` / `Syntax:Identifier:<SymbolClass>`
(dimension-syntax recovery), `GenerateBlockSymbol:unconditional` (bare
`begin`/`end` generate block), `GenerateFor:no-template` (zero-instance
loop body), `TransparentMemberSymbol:<Class>`.

## Self-check signed integral tier (2026-10-09)

The elaborated self-check surface admits signed scalar and descending
zero-based packed-vector variables, plus `byte`, `shortint`, `int`,
`longint`, `integer` and `time`, including their unsigned variants.
Widths and two-/four-state initialization follow the bound frontend
type. Signed `Var`, `LocalDecl` and `Ident` nodes carry an optional
`signed: true` field for auditability. Runtime storage remains a bit
vector: signed relational operations are encoded as `s<`, `s<=`, `s>`
and `s>=` after context propagation, not inferred from variable names.

`SignedResize` has `kind`, `span`, `width` and `operand`. It retains the
low `width` bits when narrowing and copies the source's most significant
bit when widening, including `x` and `z`. For an implicit conversion,
the source and propagated result types must both be signed; an unsigned
context uses the existing zero-filling `Resize`. In particular,
assignment to an unsigned wider destination can contain an inner signed
extension followed by a
same-width unsigned reinterpretation, while mixed-sign arithmetic and
comparison can propagate an unsigned widening context. Conversion
placement in the expression tree is significant.

The self-check compiler lowers `SignedResize` to the shared
`LVec.resizeSigned` value rule. Non-suspending statement execution uses
the existing `stepSStmt_done_agrees` correspondence, not another
scheduler. Known signed decimal output uses the two's-complement integer
and the existing natural field-width rule; unknown output retains the
existing `x`/`X` rendering.

The legacy M0 envelope now also admits signed four-state ports, variables and
nets. Their declarations and identifier nodes carry optional `signed: true`
metadata; signed order comparisons use the `s<`/`s<=`/`s>`/`s>=` operator
tags and the shared two's-complement value rule. Symbolic signed resizing is
still loud. Enums, structures, unpacked arrays, reversed packed ranges and
unsupported operators remain loud in this surface.

## Integral explicit conversions (2026-10-09)

An elaborated `ConversionExpression:Explicit` whose source and result
both have admitted integral type shapes lowers to the same existing
expression nodes on the legacy/self-check path. Scalar, predefined
integer and descending `[W-1:0]` packed scalar types are admitted;
symbolic extraction continues to refuse explicit conversions.

The cast operand is self-determined. A width change lowers to
`SignedResize` when the **source type** is signed, otherwise `Resize`,
regardless of the result type's signedness. An equal-width conversion
keeps the operand unchanged. If the source is four-state and the result
is two-state, an outer `Squash2` maps `x`/`z` to zero at the result width.
Signing casts therefore need no extra runtime node: slang's elaborated
result type already determines the signedness of later consumers and
of any enclosing implicit conversion.

Nonintegral and exotic integral type shapes remain
`Unsupported` with `sv_kind = "ConversionExpression:Explicit"`.
Bitstream and streaming-concatenation conversion kinds retain their
own refusals. This lowering changes neither the self-check parser nor
the scheduler vocabulary.

## Integral signing functions (2026-10-11)

The legacy/self-check path admits the IEEE 1800-2023 §11.7.1 / §20.5
system functions `$signed` and `$unsigned` with one admitted integral
operand. The bound argument and result must have equal bit widths and
the same two-state/four-state classification. Selected integral operands
retain their packed value width even when the selected source range does
not start at zero. The operand's expression node is retained unchanged
at runtime; its optional `signed` metadata is replaced by the function's
result signedness and `signing_cast` records the function name. Its span
covers the call. No new executable expression kind is introduced.

Signedness is consumed from the frontend's elaborated types: subsequent
implicit conversions choose `SignedResize` or `Resize`, comparisons
choose signed or unsigned operators, and output tasks retain the result's
signed decimal interpretation. A surrounding mixed-sign expression can
demand zero extension even when the call itself is `$signed`. The function
does not inherit an enclosing assignment's width; argument evaluation is
self-determined. Four-state bits are preserved until an actual two-state
destination conversion applies `Squash2`.

Pure signing calls also participate in ordinary case statements, selected
assignments and fixed-size `$bits` queries. Unsupported operands, side
effects and invalid signatures remain loud. Constant folding cannot erase
signing-call admission evidence; an erroneous compilation containing an
admitted call retains `SigningCast:invalid-compilation`. Symbolic `sv-0.2`
calls keep their existing `Cast` representation and admission boundary.

## Integral typedef declarations (2026-10-09)

On the legacy path, a bound `TypeAlias` member at module or compilation-unit
scope is omitted when its bound declared type passes `type_width_2s` or
the fixed dimension-query metadata admission: scalar, predefined integer,
enum, packed structure or untagged packed union, including fixed packed and
unpacked arrays thereof. The frontend has already
resolved alias uses, including alias chains, so existing variable and
expression nodes carry the resulting width, signedness and state kind.
No `TypeAlias` runtime node is introduced. Block-local typedefs are
elaboration-only in the bound statement tree, with variable declarations
lowered through the original runtime canonical type check. Erasing a type
alias does not admit runtime aggregate or unpacked-array storage.
Frontend errors in a compilation containing an erased alias retain
`TypeAlias:invalid-compilation` rather than disappearing with the declaration.

Unsupported module aliases retain `sv_kind = "TypeAliasType:TypeAlias"`;
unsupported compilation-unit aliases retain `sv_kind = "TypeAliasType"`.
Dynamic storage, tagged unions and nonintegral element types remain outside
this metadata admission. Symbolic integral aliases
retain their existing refusal; symbolic enum metadata is unchanged.
Runtime compilation-unit members are not erased or admitted by this rule.

## Four-state selected reads (2026-10-09)

The legacy `SelectRead` node has `kind`, `span`, `width`, `value`,
`index`, `index_signed` and `descending`. The source must be an admitted
four-state predefined integer or descending `[W-1:0]` packed scalar
vector. The selector must have an admitted integral type; its signedness
is explicit because interpreting a negative signed index as an unsigned
natural would change an indexed slice that overlaps bit zero.

For bit reads, `width` is one and `descending` is false. For a constant
part read, `index` is the bound right endpoint and `width` is the bound
result width. Indexed-up reads use the left/base operand and false;
indexed-down reads use the left/base operand and true. The evaluator
computes the low index as `index - width + 1` for descending reads, else
`index`, in integer arithmetic. It reads low-to-high into the existing
LSB-first vector, supplying `x` only for individual invalid positions.
An unknown selector returns an all-x result of the bound width.

Result signedness is unsigned, with enclosing elaborated conversions
retained by ordinary lowering. Two-state, scalar and unsupported source
shapes remain `Unsupported` with `:source-type`; unsupported selector
types retain `:index-type`. Symbolic `BitSel`/`PartSel` nodes are unchanged;
`SelectRead` does not admit selected assignment targets.
A legacy design containing `SelectRead` and any frontend error diagnostic
also carries `SelectRead:invalid-compilation` in its top-level refusals;
recovering a typed expression from malformed source is not admission.
