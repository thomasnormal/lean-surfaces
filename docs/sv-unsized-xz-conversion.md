# Unsized x/z conversion in a memory expression

The clean-room fixture is
[`Examples/system-verilog/sem2/unsized_xz_ternary_mem/unsized_xz_ternary_mem.sv`](../Examples/system-verilog/sem2/unsized_xz_ternary_mem/unsized_xz_ternary_mem.sv).
It retains the parser's `ConversionExpression:unsized-xz` node as the true
branch of `a ? 'hz1 : 'b0`, with a source-shaped dynamic unpacked-memory read
`mem[a]` beside it.  The envelope is generated by the approved Slang extractor; no source
text is re-parsed and no lowering is added.

IEEE 1800-2023 §5.7.1 makes the unsized x/z literal context-determined.  At a
concrete destination width, `instExpr2` applies the literal's canonical
32-bit, MSB-first payload: truncation keeps the low bits, while widening
replicates the payload's most-significant `x` or `z` bit.  The marker remains
parser-shaped until that point.

The model stays loud when there is no destination width or when the retained
payload is malformed.  Other conversion kinds and compound memory expressions
remain at their existing boundaries.

The fixture's Lean guard checks the retained marker, the concrete `N = 40`
and `N = 8` expression values, and the memory-route traces.  Its Icarus rows
match at both points; Xcelium uses the configured reference-simulator gate
when available.
